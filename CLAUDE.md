# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

An exploration game with smooth, dreamlike landscapes (inspired by Journey, Stray, Genshin Impact), in C# / .NET 10 using Silk.NET 2.23 (windowing, input, OpenGL). It started as a Minecraft clone: the block-based version lives on `first-version` (it was `main`; `vegetazione-blocchi` adds swaying grass to it); `terreno-realistico` replaced the blocks with a layered terrain and is kept as a milestone; `alone` (the project's code name) continued it, and `alone-build` added gathering and building; that work is now on `main`, where development continues. Targets Windows, Linux and macOS, so portability matters: keep the GL context at **3.3 core + forward-compatible** (macOS caps at 4.1) and avoid platform-specific APIs. The user communicates in Italian; in-game UI strings (window title HUD) and README are in Italian.

Roadmap on this branch: 1) smooth terrain (done), 2) objects the player can pick up and place with point lights (done; for now only small glowing crystals, lanterns and torches were removed pending a redesign), 3) instanced grass and procedural trees swaying in the wind (done), 4) post-processing (bloom, light shafts, grading), volumetric clouds, surreal elements (done). Then the **cosmic direction**, modelled on AI "cosmic purple beach" art the user shared: a violet/indigo/magenta world with cyan accents, a giant spiral galaxy, bioluminescence everywhere, dark silhouettes. The day/night cycle stays, but its brightest moment is a twilight. Phases: A) sky, palette and cycle (done), B) water with sky reflections and a bioluminescent shore (done), C) giant crystal clusters and glowing flowers (done), D) crystal stepping-stone paths (tried, removed: the stones could not be climbed), E) creatures (butterflies, birds, fish) and palms (done).

## Commands

```
dotnet build                 # debug build
dotnet run -c Release        # play
dotnet publish -c Release -r <win-x64|linux-x64|osx-arm64> --self-contained -p:PublishSingleFile=true
```

For now (debugging) the game starts in a 1280×720 window; `MINE_FULLSCREEN=1` starts full screen at the monitor's own resolution (no display mode change; `Game.SetFullscreen`), F11 or Alt+Enter toggles between the two, F10 moves the game to the next monitor (`NextMonitor`). `GpuPreference` (src/GpuPreference.cs) sets the Windows per-app "High performance" GPU preference for the running exe at startup and, the first time, restarts the game once so the discrete GPU is used.

There are no tests and no linter. The SDK lives at `C:\Program Files\dotnet\dotnet.exe`; if `dotnet` is not on PATH in the current shell, call it by full path. To verify rendering changes, launch `bin\Debug\net10.0\Mine.exe`, screenshot its window and kill the process (the game captures the mouse in raw mode while focused). Where screenshots are not possible (macOS without screen-recording permission), at least launch it for ~10 s to catch shader compile errors (they throw at startup), and measure with the debug environment variables: `MINE_FPS_LOG=1` prints the GPU name at startup and the HUD line (with FPS and the grass blades drawn) to the console every half second, `MINE_RAIN=1` starts with rain, `MINE_TIME=0.9` sets the time of day, `MINE_PITCH=0.3` the view pitch (radians), `MINE_YAW=3.14` the heading, `MINE_POS=600,840` spawns exactly there (in water the player floats up), `MINE_HEIGHT=70` starts flying that many metres above the ground (for views over the land), `MINE_GIVE=1` gives 99 of every material, `MINE_DEMO=1` builds a small block house (`Game.BuildDemoHouse`) ahead of the classic spawn (always there, wherever the player starts), `MINE_BUILD=1` starts in building mode, `MINE_SLOT=seeds` (or wood, stone, crystal) starts with that material in hand, `MINE_BREAK=10` acts as if the left button were held from 10 s on (to film breaking), `MINE_SAVE=path|none` picks the save file, `MINE_SHOT=file.png` (with `MINE_SHOT_AT`, default 15 s) saves the finished frame as a PNG from the game's own framebuffer and quits (`Screenshot`; works where the screen cannot be captured, e.g. a locked Mac: the game starts windowed), `MINE_NO_VSYNC=1` uncaps the frame rate (use it when measuring), `MINE_SKIP=sky,grass,...` skips passes (shadow, terrain, grass, trees, sky, water, post) and `MINE_GPU_PROFILE=1` prints the GPU time of each pass (`GpuProfiler`, timer queries; on Apple GPUs they overstate, so compare FPS with passes skipped instead). A window can be captured on macOS with `screencapture -l<window id>` (id from `CGWindowListCopyWindowInfo`). On a MacBook Air M1 (Retina, 2560×1440 rendered) the game runs at ~62–67 FPS uncapped in the open and ~55–57 in the thickest woods (tree pixels use the full lighting): the cloud ray march (~2.7 ms at half resolution), terrain and grass shading, point lights (~1.6 ms at night) and post (~2.5 ms) are the main costs; moving grass lighting to the vertex shader was tried and was much slower (millions of blade vertices).

## Architecture

`Game` (src/Game.cs) owns the window, input callbacks, the inventory and the world shaders, and drives the loop: `Player.Update` → `DayCycle.Update` → `TreeField.Update` (+ trunk collision) → `TerrainRenderer.Update` → `TreeRenderer.Update` → `GrassRenderer.Update` → `WorldObjects.Update` (+ aim), then collect point lights → render shadow map (terrain + trees + islands + objects) → `PostProcess.BeginScene` (HDR buffer) → trees → grass (culling off) → terrain (last of the three: the trees and grass fill the depth buffer first, so the terrain under them skips its costly shading; ~1.9 → ~0.3 ms in a meadow at 1080p) → objects → islands → sky (last, see below) → motes → `PostProcess.Finish` (bloom, grading to the screen) → crosshair. All scene shaders output linear HDR; tone mapping lives only in the composite pass. Starting, the screen is black with the title in it (`TitleCard`: ALONE in huge heavy extended capitals, 94% of the screen wide, modelled on a reference the user picked: a trapezoid A with a small triangular counter and a notch between the feet, a wide L, a slightly oval O with a small counter, an N cut by two diagonal notches, an E with thin slits; measured in cap heights in `LetterSpans`, rasterised row by row at screen resolution with the HUD's rectangles, runs of one colour merged, no stencil). The letters turn white over `TitleInSeconds`; once the land, grass and trees around are built (`TerrainRenderer.Ready`, `GrassRenderer.Ready`, `TreeField.Ready`; about 4 s on an M1, `LoadingMaxSeconds` 12 at most; `MINE_FPS_LOG=1` prints the time) and not before `WhiteSeconds` 2.2, they turn see-through over `OpenSeconds` 0.9 (the world showing through them, already whole: holes from the start showed the grass being built), and without a pause (overlapping the letters' last `FadeOverlap` 0.2 s) the black goes on emptying, more slowly, over `FadeInSeconds` 2.4 (`Game.DrawLoadingFade`; screenshots taken before then come out dark). The window title and the menu show the game's state (`UpdateTitle` builds `_info` every half second). Esc opens and closes the menu (`DrawPanel`, at the top in the middle of the screen: an Info column (position first) and an Options column side by side, all text the same size; `MINE_MENU=1` opens it from the start): the position, then FPS, world, time and weather, then the options, switched by their keys only while it is open (`OptionKeys`: V vsync, M world saving, I full screen (not saved), X quits the game (`QuitOption`, an action; letters the game does not use, since it goes on while the menu is open); `ToggleOption`), saved in `SaveData.Options` (`GameOptions`; null = default). With `GameOptions.SaveWorld` off, `SaveState` clears `SaveData.Worlds` and `LoadWorldState` loads nothing: each start is a fresh world (the inventory and the options are still saved). The menu lies over the game, which goes on as if nothing were open: the mouse stays captured and hidden, everything keeps working. There are no on-screen hints, no low quality mode (removed: clouds always march 32 steps, the scene renders at full resolution), and the menu does not show movement or the item in hand. Units are metres; Y is up.

**The world and its biomes (`GroundMaterials.Biomes`).** There is one world, procedural, made of five biomes that always blend into each other gradually (they replaced the old world presets and their Ctrl+1..5 switching; `WorldPreset` now only holds look knobs, `Magic`, `Saturation`, `ClearSky`, `PlainNight`, `ColorVariety`, `PlanetRim`, all at their defaults, and the name `mondo` that keys the save). The climate is a very broad temperature noise (`TemperatureAt`, features ~2 km): hot → **Deserto** (`HotLow`..`HotHigh`), cold → **Innevato** (`ColdHigh`..`ColdLow`), mild in between, so desert and snow never meet; in the mild lands a sea noise raises **Isole** (`SeaLow`..`SeaHigh`) and a relief noise **Colline** (`HillLow`..`HillHigh`), the rest is **Prateria**. `Biomes(x, z)` returns the five shares (`BiomeMix`, summing to 1; `Dominant()`, `Names`), each change a smoothstep over a couple of hundred metres; about a fifth of the land each, regions a kilometre or two across (tuned with a Python replica of the noise). `Desert`/`Snow` give one share alone; the shader mirrors them (`temperature`, `desertWeight`, `snowWeight` in `Materials`: keep in sync). What each biome has plenty or little of: the **desert** is sand and dunes on raised land (hardly any lakes), full of rock spires (`SpireChance` 0.45 in its heart), palms in oases (`AddPalmGroves`, anywhere in it) and small dry shrubs (its tree family is mostly `Cespuglio secco`, 0–3 per cell, no woods: `WoodsThreshold` 0.9), grass very rare (`GrassDensity` 0.12, and its sand holds none); the **prairie** is a wide gently rolling plain, the thickest grass (`GrassDensity` 1.15) and most tall grass meadows (`TallGrass` threshold lowered), flowers, lone trees and few woods (threshold 0.32), many lakes; the **hills** are tall rolling hills, thick woods (threshold -0.02), lakes; the **islands** are sea with islets (`IslandShape`, the old archipelago: sandy shores, wooded hearts where `Forest` rises inland), palms; the **snowy lands** are hills a little higher, always white (the shaders' `snowCover`: everything facing up, in drifts, from the ground map's snow), often snowing (`Weather.Update(dt, snowyLands)`: spells of `SnowSpell` 250 s in every `SnowCycle` 330 s while the player stands in them, which lay no world-wide `SnowCover`); everywhere else a shower passes by itself now and then, rarely (`Weather` showers: one may come every `ShowerGapMin`..`ShowerGapMax` 15–35 min of play, lasting `ShowerMin`..`ShowerMax` 100–220 s; over the desert only `DesertShowers` 15% of them fall; never starting in the snow and stopping as the player walks into it; key 2 stops one too), pines (tree family `SnowBiome`: pines, a cypress, a bare tree), sparse grass (0.3), no butterflies (they spawn only where `Snow` < 0.25 and turn back from it) and no birds (flocks fly off as the player walks in), no lotus, reeds, palms, bells or light gardens, the odd starflower. Heights blend the biomes' shapes by their shares (`TerrainField.BaseHeight`). The HUD/menu shows the biome the player is in (`Bioma: ...`). The game starts in the heart of a prairie nearest the origin (`FindSpawn`); floating islands are off (`IslandField.Enabled`, they belonged to the classic world). Butterflies spawn only over grass (`GroundMaterials.GrassWeight` > 0.5), so they are rare in deserts.

**Rock spires as blocks.** The rock spires (mostly in the desert, a few in the hills and snowy lands: `SpireIn`, cached per cell) are no longer part of the terrain's height (`SmoothHeight`/`Height` leave them out; `TerrainField.SpireHeight`, `SpiresNear`, `HeightWithSpires` give them): `Blocks.UpdateSpires` (every 16 m the camera moves) lays each spire within `Blocks.SpireRadius` (600 m) as natural stone blocks, solid through, every column a stack from the 1 m level at or just under its ground (so all spire blocks share one grid and hide each other's faces), and takes them away beyond 700 m; dug natural blocks are remembered (`_dug`, saved as `WorldSave.Dug`), natural ones are not saved. The terrain never includes the spires. Farther than the laid blocks, `BlockRenderer.UpdateFar`/`DrawFar` draw every spire within the view distance as the very same blocks (`Blocks.SpireLayout`: the same columns, dug blocks left out (`DugIn`), veins; a column two spires share goes to the taller), one plain quad per visible face coloured as the near block's squares on average (`FarBlock`), built on the thread pool and drawn while the spire is not laid (`SpireLaid`): nothing changes shape when the real blocks take over (the terrain's coarse far tiles used to turn spires into a few 16–32 m steps). ~0.1 ms. `BlockRenderer` draws natural blocks as the terrain's rock with strata in a 2×2 grid (lighter meshes) and skips buried faces (`Blocks.GroundAt`, a cached terrain height per column). Nothing grows in a spire's footprint (`GrassGrowth`, trees, decorations, crystals, spawn), islands and flocks keep clear of them. About 10 spires (~43k blocks) are laid around the desert spawn, at a steady 60 FPS. Glass and crystal are minerals found only as veins in the spires (the crystal clusters are no longer generated): `Blocks.Vein` picks them per natural block from thin sheets where a 3D value noise crosses zero, broken into patches by a coarser one (`GlassVeinWidth`, `CrystalVeinWidth`; ~9% of spire blocks glass, ~2.5% crystal, some spires with none); `_veins` holds them, `VeinAt`/`MaterialAt` answer, `Remove` gives the mineral instead of stone; a vein block breaks like stone with chips glinting of its mineral, and `BlockRenderer` draws it in the 4×4 grid (`Vein`), the two told apart at a glance: glass cold and unlit (pale cyan nuggets, some with a white glint, in paler greyer rock), crystal glowing (hot violet nuggets, emissive 1.3, in rock stained violet and faintly glowing).

**Gathering and building (branch `alone-build`).** `Inventory` (src/World) has `SlotCount` (5) slots, each a stack of one `Resource` (wood, stone, crystal, grass seeds, glass) of any size; picked-up material joins its stack or the first empty slot (`HasRoomFor`, `Add`, `Take`, `Spend`); the mouse wheel picks the slot in hand (`Game._slot`; a trackpad swipe is tamed in `OnScroll`: the first event of a gesture steps at once, then a step needs `ScrollNotch` of scrolling and `ScrollInterval` since the last). For now (to try building) every start sets each material to exactly `Game.TestStock` (100); counts over 999 show as 1K, 12K... so they fit their slot. Breaking: `TreeModels.YieldOf` says what a tree style or palm (wood) or crystal cluster (crystal cubes, `Round(5.2 × scale)`: 3 to 12; translucent clusters give as many glass blocks; the clusters are no longer generated: see the veins in the spires) gives (the round `Rocks` boulders were removed: stone comes from digging the rock spires, see below), how long it takes, how it is aimed at (a vertical capsule) and its chip colours (bark and foliage, or stone); `TreeField.Pick` finds the nearest along the view ray. Controls (no modes): the left button (held) breaks, the right button places one block of the material in hand per click. Holding the left button (`Game.Gather`) on a tree, rock, crystal (a cluster, or a small `WorldObjects` crystal: `TreeModels.SmallCrystal`, 2 cubes, though none are generated any more) or block, or aimed at a meadow (tearing up grass: `Game.GrassAt`, the ground under the crosshair when nothing else is: a meadow not torn up, or grown planted grass; the whole terrain tile under the crosshair within `BuildReach` counts (`AimedTile`, also used to sow), if any of its four columns holds grass (`_mowTarget` is the tile centre; aiming at a single plant was too fiddly; `GrassAt` mirrors `GrassRenderer`'s tests, a little more generously, so no visible grass is left out): in `MowSeconds` 0.12 s the tile's grass bursts into chips of its colour and `Blocks.TearUp` tears it up for good (`_torn`, saved as `WorldSave.TornGrass`: `GrassGrowth` 0 there, flowers go too; no grass grows back), dropping `Resource.Seeds` (`ItemMeshes.Seeds`: the pixel-art icon, four lozenge grains on a 16×16 grid, outlined, teal or violet with a pale glint, extruded into relief by `SeedPixels`, one box per pixel, each grain thickest along its middle; a sod block with swaying blades, a handful of stirring faceted 3D grains, then the flat card were tried first. In hand they are a squat glass jar, for now cubic (`ItemMeshes.SeedJar`, built with `Lathe`, radii as apothems; `JarSides` 4, 10 gives the round faceted jar tried first: wooden lid, twine band, 120 small extruded grains filling two thirds of it) drawn by `DrawHeldItem` big (scale 0.6) with its bottom out of the view, so the missing hand is not noticed; each throw flicks it forward and up, mouth toward the ground, and back (`FlickSeconds` 0.35 s, from `_thrownAt`); the inventory icon is the jar too (`IconRenderer`, its glass blended over the grains with `uGlass`): the solid parts, then the glass blended over them (far side, then near side) in the object shader's glass mode (`uGlass`: tint, Fresnel sky reflection, sun glint, premultiplied alpha)) one per tile; with seeds in hand the right button sows (`Game.Sow`): a glowing handful arcs from the hand (`Debris.Throw`) and after `SowFlight` 0.55 s `Blocks.Plant` greens the tile where it lands (one seed, one tile), whose top looks watered, darker and cooler, for `Blocks.WetSeconds` 3 s, dry by `DrySeconds` 9 s (`Blocks.Plantings`, the alpha channel of `IndoorMap`, `wetGround` in the terrain shader, refreshed every 0.25 s while `GroundDrying`; drying with the grass's growth, ~2 min, was too long), on `Plantable` columns (bare ground above the water, torn-up meadows or sand alike; `Blocks.CanPlant` checks first, so no seed is wasted; where nothing can be sown, e.g. grass already there, no message: the jar's flick starts and stops short, `_balkedAt`/`BalkSeconds`); holding the button sows a strip, a seed every `SowInterval` 0.3 s wherever the aim has moved on to another tile: `_planted` (Unix ms, saved as `WorldSave.PlantedGrass`, so it grows on while the game is closed) grows from small to full over `PlantGrowSeconds` 120 s, and `GrassRenderer.Planted` lets blades grow there whatever the ground; butterflies spawn over real grass only (`Creatures.GrassFor`: not torn up, planted once `ButterflyGrass` 0.6 grown); `GroundChanged` is raised once per 32 m cell (`RaiseGroundChanged`), as grass tiles and tree cells rebuild whole; no progress bar for it), (a block takes `BreakSeconds` and gives itself back as a cube) sprays chips from the point hit (`Debris.Chips`, 30 a second) and after `Yield.Seconds` breaks it: `Debris.Burst` throws chips out of its body, `Debris.Spill` throws one cube per unit of material, and `TreeField.Gather` records its exact position in `_gathered` for good (generation is deterministic, so `Generate` leaves it out forever). `Debris` (src/World) simulates the chips (gravity, bouncing off the sides and ceilings of blocks (`Ground.Solid`), damped bounces on `Ground` taken in their own column only (`blockRadius` 0: with the player's 0.2 m disc a cube beside a wall found the wall's top and climbed the rock block by block), spin, shrinking at the end of their life) and the material cubes: they fall, then float spinning over the ground; once settled (or after 0.8 s) within `AttractRadius` (2 m, so things lie waiting until the player walks up to them) of the player's chest they fly to the player (`AttractSpeed`, caught within `CollectRadius`) and go into the inventory (not if it is full). `CubeRenderer` draws them instanced (per model: the chip cube, tinted per instance, and each material's `ItemMeshes` model) with `TerrainShaders.CubeVertex` (position, size, quaternion, tint per instance) and the object fragment shader. `IconRenderer` draws each slot's material model turning over the HUD (between two `Hud` batches: the slots, then the counters). Building uses 1 m blocks, Minecraft style (src/World/Blocks.cs): a `BlockPos` is a 1 m column and the height of its bottom in steps of `Blocks.Step` (0.5 m, the terrain's layers), so a block set on the ground sits on its tile (blocks side by side may be offset by half a metre). The material in hand (wood, stone, crystal: violet glass that glows and lights the night, `Blocks.Lights`, the nearest 6; glass: clear, see-through blocks for windows, see Glass below) goes where `Blocks.Plan` says: against the face of the block aimed at (`Raycast`: a 2D DDA over the columns, testing each block's box) or on the terrain tile aimed at, unless it would overlap a block (`Overlaps`), the player, a trunk (with a margin) or be buried (`Problem`). Breaking a block gives it back as a cube. The player stands on blocks through `Ground` (`Blocks.GroundBelow`: blocks whose bottom is at the probe height or below, over a 0.2 m disc so an edge still holds) and `Blocks.ResolveCollision` pushes them out of blocks beside them (above the step height) and stops them rising into one overhead (the body is `Player.Height` 2 m tall and `BodyRadius` 0.35 m, the eyes 0.2 m under the head so the view never reaches into a ceiling: passages two blocks high let the player through). A block near the ground clears grass and flowers in its column and the ring around it (`GrassGrowth`, 0 there, growing back to 1 over `RegrowSeconds` once cleared no more; `GrassRenderer.Growth` drops tufts above the growth and shortens the rest, `TreeField.Covered` drops trunkless decorations; `GroundChanged`/`GrassGrowing` rebuild them). Indoors means under a block (`Indoors`: a block above in the column): butterflies turn back (`Creatures.Indoors`) and never fly into a block (`Creatures.NearBlock` = `Blocks.Near` with `WingMargin` 0.45 m: one caught by a block flies off, one heading into a block within 0.6 s turns back, a step that would touch one is not taken), and `IndoorMap` (a 128×128 RGBA16F texture of 1 m columns around the camera, unit 7, `IndoorMap.Glsl` `indoors(p)`: the ground −1 m and the bottom of the column's highest block) keeps motes, rain, snow and the lightning flash (`uFlash`, separate from `uAmbient` in `litColor`) out. `BlockRenderer` meshes each chunk of `Blocks.ChunkSize`² columns (only faces without a block right against them, each a 4×4 grid of little squares shaded like the material cubes: bark with rings on the ends, speckled stone, glowing glass), rebuilt only when a block in or next to it changes (`TakeDirtyChunks`), drawn with the object shader (and into the shadow map). There is no preview or highlight of where the next block goes (tried, the user did not want it). The held material is drawn big, low on the right of the view (it fills the corner where a hand would be), with the object shader after clearing depth (`Game.DrawHeldItem`, meshes in `ObjectRenderer.DrawItem`; it bobs while walking and chops while gathering; switching slots, the one in hand sinks out of the view below as if put in a pocket and the new one rises from there, overshooting a touch: `UpdateHeldSwap`, `_swapOut`, `SwapOutSeconds` 0.14, `SwapInSeconds` 0.26, `_shownItem` is what is drawn meanwhile; an emptied slot's item just sinks away). The HUD (`Hud`: a 5×7 pixel font generated in code, capitals only with accents dropped, rectangles, drawn after the crosshair) shows the inventory as a column of slots in the middle of the left edge (the one in hand framed in pink with a soft pulsing pink halo; left alone it slides out of the screen to the left: `InventoryHideDelay` 3 s after the wheel last turned it leaves over `InventoryOutSeconds` 0.4 s, and the wheel, or a cube caught into the bag, brings it back in place over `InventoryInSeconds` 0.6 s; `_inventoryShown` 0..1 goes linearly; coming in the position is a damped spring `1 - cos(3.5πt)·e^(-4.5t)` (it springs a quarter of the way past its place to the right and settles with smaller bounces), going out `1 - easeInBack(1 - shown)` (back 2.6: it first draws back to the right); a fade was tried first and replaced), the progress of the blow while breaking (nothing aimed at is ever named), and messages (`Game.Toast`). `SaveGame` writes JSON (application data folder, Mine/salvataggio.json): the inventory slots, and per world (by name) the blocks, what was broken, the cubes left on the ground (`Debris.Save`/`Load`), the crystals taken and placed (`WorldObjects.SaveTaken`/`SavePlaced`/`Load`); it is loaded in `BuildWorld` before anything around is generated, written every `AutosaveSeconds` when something changed, on a world switch and on closing.

**Glass.** See-through glass is drawn in its own pass right after the water (before the waterfalls), premultiplied-alpha blended with no depth writes, each thing twice (far side with front faces culled, then near side: `Game.BeginGlass`/`GlassBackFacesDone`/`EndGlass`), shaded by `glassColor` in the shared `Lighting` GLSL (tint lit faintly, Fresnel sky reflection, sun glint, `glow` for brighter, more opaque parts, fading into the edge fog), switched on by a `uGlass` uniform in the object, cube and tree shaders. What goes in it: glass blocks (`BlockRenderer` keeps a second mesh per chunk, `DrawGlass`: each visible face a clear pane in a thin frosted, faintly glowing rim, so a wall reads as panes; faces between glass blocks are dropped, glass hides no solid face; not in the shadow map, so light passes), the panes of glass cubes lying around (`CubeRenderer.DrawGlass`, sharing the instances of `Draw`), and the translucent crystal clusters (`TreeModels.Decoration.ClearCrystals`: glass prisms each round a thin glowing core, on the dark plinth; no longer generated, like all crystal clusters; `Prism(glass: true)` stores the glow as -1 - glow, and `TreeVertex` moves the vertices of the other pass outside the clip volume, so the normal pass skips the glass and `TreeRenderer.Draw(translucent: true)` draws only the variants with glass (`TreeModels.Translucent`)). Held and inventory models may have a glass part too (`ItemMeshes.Carried`/`GlassOf`: the seed jar, the glass cube's panes inside a pale frame). `MINE_DEMO=1`'s house has glass windows.

**Terrain shape (`TerrainField`).** The land is layered: square tiles of `TileSize` (2 m), each flat at a multiple of `LayerHeight` (0.5 m), with vertical walls between. `SmoothHeight(x, z)` is the continuous surface they are cut from (2D `PerlinNoise`: continental swells, domain-warped hills, round-crested dune ridges, detail, each biome its own shape, blended by the biomes' shares; slopes are kept gentle so ~99.5% of neighbouring land tiles differ by at most one layer (walkable), larger steps being rare; `Lakes` scoops at most one lake per `LakeCell` (400 m; `LakeIn`, cached per cell, holds one by the biomes there: many in the prairie and hills, some in the snow, hardly any in the desert, none among the islands) on low and middling land (not where the continent noise is high): a wobbly shore `LakeMinRadius`–`LakeMaxRadius` across, banks sinking gently over `LakeBank` to just under the water, a floor `LakeMinDepth`–`LakeMaxDepth` lower toward the middle; below `WaterLevel` the land drops `DepthScale` times faster, so shores stay gentle and the water gets deep. `Height(x, z)` = `TileHeight` = the smooth height at the tile centre snapped with `Layer`. `Normal` is the smooth surface's normal (used for "how steep", e.g. where trees and crystals may grow). `InsideTile`/`TileCenter` keep things placed on a tile's flat top. Pure and thread-safe; no stored terrain data.

**Terrain rendering (`TerrainRenderer`).** Chunks of 64 m out to `ViewDistance` (1300 m). Each chunk is a grid of flat blocks (terrain tiles near the camera, merged 2×2, 4×4… farther away per `LodSteps`/`LodRanges`, each merged block at the layered height of its centre) plus vertical walls where neighbouring blocks differ; walls on the chunk border reach deeper (skirts) to hide cracks against other levels of detail. Non-indexed triangles, vertex layout position, normal, slope (smooth normal.y: picks the material, 0 on walls → rock), ao (walls darker at the foot). Meshes are built on background worker threads fed by a `BlockingCollection`, nearest first, and uploaded on the main thread at most `UploadsPerFrame` per frame; a chunk keeps drawing its previous mesh until the new one arrives, and stale results are dropped. `Draw` skips tiles well behind the camera; `DrawNear` draws only the tiles around a point for the shadow map.

**World shaders (`TerrainShaders`).** By day `litColor` warms the sky fill (half-way toward a warm tint of its brightness), and the Noon/Day keyframes use golden sunlight and warm ambient, so noon never reads as bluish. Terrain and object shaders share the private `Lighting` GLSL (pasted after `SkyRenderer.Glsl`): `litColor` = albedo × (generous ambient mixing the keyframe ambient with the sky colour around the normal + Lambert sunlight × shadow map + point lights), and `finishColor` = aerial haze + light halos + edge fog + tone map. Point lights skip pixels beyond their radius, and halos skip lights whose ray passes over 8 m away (lowered by their value there so they still fade to zero): both loops run over up to 16 lights per pixel and were a large share of the frame. Terrain materials are procedural, from slope and height: grass (drifting between green, golden and a teal accent), warm sandstone with faint wavy strata on steep slopes, pale sand in the lowlands, plus grain that fades with distance (not computed past 140 m). Each noise is computed once per pixel and handed to the `...For` variants of the material functions (`biomeWeightsFor`, `grassColorFor`, `rockSandFor`; they used to be recomputed up to four times). The slow part (grass colour and desert share, seven noises) comes from `GroundMap` (src/Rendering/GroundMap.cs): a 1024² RGBA16F texture, 2 m a texel over 2048 m around the camera (unit 8), drawn by the GPU with `TerrainShaders.GroundMapFragment` (the same `Materials` GLSL, so it cannot drift) when the camera has moved 128 m and recreated with the world; past its edge the terrain shader computes them itself. With the draw order this took the desert terrain from ~1.85 to ~0.85 ms at 1080p on the RTX 2060, identical on screen.

**Shared GLSL.** `SkyRenderer.Hash` (`hash13`, any stage), `SkyRenderer.SkyGradient` (`skyGradient(dir)`, the sky without its bodies, i.e. `skyColor(dir, false)`, with its uniforms; any stage, part of `Glsl`) and `SkyRenderer.Glsl` (sky; fragment only, it uses `fwidth`). In `TerrainShaders`: `Wind` (`windOffset`), `TreeTransform` (`treeWorld`, used by both the tree shader and the shadow pass), `Materials` (noise, `grassColor`, `rockSand`), `Lighting`. Defining `CHEAP` before `Lighting` (grass) uses one shadow tap, no haze noise and no halos. `GroundMaterials` (src/World) is a C# mirror of `grassColor`/`rockSand` so grass is coloured and culled on the CPU: keep the two in sync.

**Colour families (`GroundMaterials.Biome`).** Within the biomes, four colour families from large-scale value noise, computed identically in C# (`Biome`) and GLSL (`biomeWeightsFor`, given the desert's and snow's shares, in `Materials`): indigo woods, pink woods, turquoise woods (bands of a "flavour" noise, splitting the mild biomes) and the desert; the snowy lands count as indigo. Each pulls the grass patches 40% toward its hue (the five-hue patch mix stays), so ground and blades agree; deserts are covered in warm peach sand with faint ripples (`rockSand`/`GrassWeight` count it as sand: no grass). `TreeField.PickBiome` draws a family by the weights at each point (the snowy lands' pines first), so trees and flowers of neighbouring families mingle across borders. The ground map (`GroundMap`) stores the grass colour and, in alpha, the desert's share minus the snow's (they never meet); every world shader reads the snow from it (`groundSnow`, `snowCover` in `Lighting`, which replaced direct `snowOn` calls; held items skip it: `uSnowless`).

**Grass (`GrassRenderer`).** 8 m tiles within `Radius` (70 m), built on the thread pool: blades grouped in tufts (`MinTuft`–`MaxTuft` blades sharing one root within a few cm, each facing its own way around the tuft and leaning out, outer ones shorter and bent more, all sharing the thinning key so tufts thin out whole), tufts crowded in clumps (up to `MaxTuftsPerClump` within `ClumpRadius`, clamped to the terrain tile's flat top), some tufts short and spreading (`CarpetMin`–`CarpetMax`, fewer in tall meadows) to carpet the ground, at `BladesPerSquareMetre` (42; a little more in tall meadows) with heights interpolated from a 1 m grid, kept only where `GroundMaterials.GrassWeight` says grass, and uploaded as one instance buffer per tile (root, bend, facing, height, thinning key, colour variation, ground colour). Grass colour comes in patches of one hue (teal, violet, magenta, lilac gold, sky blue: `grassColor`/`GrassColor`, kept in sync). No blades grow below 1 m over the water: the shores hold reed clumps instead (see Decorations). Blade height is `MinHeight` plus a random share of a maximum that grows in the tall grass meadows (`GroundMaterials.TallGrass`: thigh-high, and over head height in their hearts; taller blades are broader). Each blade is a triangle strip with no vertex data, shaped in the vertex shader from `gl_VertexID`: 7 vertices near, 5 beyond `FiveVertexDistance` (12 m), 3 beyond `ThreeVertexDistance` (28 m) (`uBladeVertices`, set per tile). The shader thins blades out with distance (survivors get wider; each tile's blades are sorted by thinning key and `Draw` issues only the prefix that can survive at the tile's nearest point, the same formula as the shader: keep them in sync; the tiles are small because of this: 32 m tiles sent 2.2 times the survivors, 8 m ones 1.26) and sways the tips with the wind. `Draw` sorts the tiles nearest first (early depth rejection) and skips those whose box (`MinY`/`MaxY`, plus `LeanMargin`) is outside the frustum. Blades are lit with a wrapped diffuse, a normal turned toward the camera horizontally only, and backlight when looking toward the sun; the sky light and the fog's sky colour are computed per vertex (`vSkyFill`, `vFogSky` with `SkyRenderer.SkyGradient`, passed to `litColorSky`/`finishColorSky`) and the shadow is looked up once. Changes to the ground rebuild the tiles of the 32 m cell (`InvalidateCell`), growing planted grass only its own tile. Measured on the RTX 2060 at 1920×1080 (classic spawn meadow): grass went from 1.47 ms (462k blades sent) to ~0.55 ms (158k); about half is now vertices and rasterization, half shading.

**Trees.** `TreeField` (src/World) places trees per 32 m cell on the thread pool, within `Radius` (950 m): thick where a forest noise is above `WoodsThreshold` (by biome, see The world and its biomes; 8 to ~20 canopy trees per cell plus half as many shrubs and saplings as undergrowth), the odd lone tree elsewhere (`LoneTrees`, by biome), small dry shrubs in the desert, only on gentle ground above the sand and never in tall grass meadows; the biome picks the family (`Canopy`, `Undergrowth`), and within it each grove (Voronoi regions around points jittered on an 80 m grid, `GroveSpecies`) is dominated by one species, with `OtherSpeciesChance` of another. `ResolveCollision` pushes the player out of trunks. `TreeModels` builds 16 procedural styles (incl. a 15 m giant, a weeping willow, a tiered pine, a sapling, a shrub, and three bare dry ones for the deserts: `Bare` styles have no foliage, their branches forking twice into twigs via `AddTwigs`, and far away keep only the thicker branches) (tapering curved trunk, branches, crowns of noise-displaced ellipsoid blobs; two with glowing orbs) at 4 levels of detail from the same random structure, the last one a single-ellipsoid silhouette (a plain 20-triangle icosahedron crown: beyond 380 m there are ~10k trees). Palms are built likewise; from level 2 their fronds are flat, and the last level is a silhouette (three-sided trunk in three pieces, six fronds of two steps: ~200 vertices instead of ~800). Reeds vanish past 220 m (`MaxDistance`). This took the trees from 5.6 to ~3 M vertices a frame and ~1.8 to ~1.2 ms (classic spawn, RTX 2060); what is left is mostly levels 0–1, which also cast shadows. Vertex layout: position, normal, colour, emissive, sway (0 at the trunk foot, 1 on leaves). `TreeRenderer` draws one instanced batch per variant and level (instances: position, yaw, scale), re-sorting into levels when the tree set changes or the camera moves 8 m; each batch's instances are grouped into the near ones (40 m) and 16 direction slices, and `Draw` skips the slices out of view (runs of visible slices are drawn by pointing the instance attributes at their first instance, GL 3.3 having no base instance); levels 0–1 (within 170 m) also cast shadows through the shadow map's instanced path (`SetInstanced`).

**Post-processing (`PostProcess`).** The scene renders into an RGBA16F colour + 24-bit depth texture framebuffer. Bloom: 13-tap downsample chain over 6 half-size levels (the first with a soft threshold, `BloomThreshold`), tent-filter upsample added back with additive blending. (Screen-space light shafts were removed: their radial blur stamped rows of blobs.) The bloom prefilter and the composite turn NaN/inf pixels black and cap the rest, since some GPUs produce NaNs where others do not (keep GLSL `pow` bases non-negative for the same reason). Composite: scene + bloom + shafts, exposure, the soft-shoulder tone map, saturation, split toning, vignette, dither.

**Sky and clouds.** The sky is drawn after the opaque geometry, at the far plane with `DepthFunc(Lequal)` and no depth writes, so its cost is paid only on visible sky pixels. The cloud ray march runs before it in its own pass (`SkyRenderer.DrawClouds`) at half resolution into an RGBA16F texture (scattered light, transmittance), skipping texels whose 4×4 full-resolution footprint in the water snapshot's depth holds no sky; the sky shader samples it bilinearly (unit `CloudsUnit`). This took ~45 to ~56 FPS on an M1 with no visible change. The moon (`moonSurface`) is a lit sphere, not pixelated: pale lilac silver, violet seas and grain from the cloud noise, `moonCraters` at two scales (bowls shaded from the light side, raised rims), a fixed gibbous phase with a soft terminator and a faintly glowing dark side, limb darkening, kept well below white (bright values washed out its texture), softly edged and veiled 30% toward the sky colour so it sits in the sky; `moonHalo` adds a corona, a wide halo and a faint ice ring. Its disk is opaque: nebulae, galaxy and stars are masked behind it. At night the clouds are darker masses (ambient × 0.55) with bright moonlit silver edges, galaxy-tinted tops (lightning flashes were tried and removed: the user did not like them). Clouds are ray-marched through a slab (`CloudBottom`–`CloudTop`, 260–760 m; a very broad noise raises or lowers the coverage threshold, opening clear skies between banks of towering clouds with dark bellies and bright rims) in `SkyRenderer`: `cloudDensity` samples `CloudNoise` (a tileable 64³ R8 texture generated at startup, bound to unit `SkyRenderer.CloudNoiseUnit`), blurred via `textureLod` as steps grow; each sample marches a few steps toward the light for self-shadowing (32 steps; the coverage threshold, `cloudThreshold`, is read once per step and reused by its light samples, and a step far outside any cloud (`cloudDensityRaw` < -1.2) makes the march skip the next one), with a two-lobe Henyey-Greenstein phase (silver lining) and interleaved-gradient-noise jitter. `cloudDensity` is part of `SkyRenderer.Glsl`, so the world shaders use it for moving cloud shadows (`cloudShadow` in `Lighting`).

**Waves.** The water shader draws breaking waves along the depth contours of the smooth sea floor: `SeaFloorMap` (unit 6) holds `TerrainField.SmoothHeight` over 512 m round the camera (256², built on the thread pool when the camera moves 64 m), because depths read from the layered tiles would make the wave fronts blocky. Bands of phase `depth / 1.6 + time` roll shoreward, rear up below 7 m, break into bubbly pink-white foam (trailing behind the crest) below ~3 m, with a cyan glow on the rising face; each wave varies in strength along its length.

**Water.** `TerrainField.WaterLevel` (15 m) is the sea and lake level; sand covers the shores just above it (keep `rockSand` in the shader and `GroundMaterials` in sync), trees stay 5 m above it, grass 1 m. `WaterRenderer` draws one quad at that level following the camera (culling off); the terrain hides it wherever it rises above. Before the water, `PostProcess.SnapshotForWater` blits the scene colour and depth into copies (units 3 and 4) so `TerrainShaders.WaterFragment` can refract the bottom (bent by ripples, absorbed toward deep indigo with the view-space thickness, from linearized depths) and reflect `skyColor(r, true)` with Fresnel, plus a glint path toward the light and bioluminescence (ridged-noise veins pulsing in the shallows, a glowing line at the shore, sparkles). `Ground` keeps the player's feet at most `WadeDepth` below the surface. Order: opaque → snapshot → clouds (half resolution) → sky → water → motes.

**Floating islands.** `IslandField` (src/World) places at most one island per 420 m cell within 1700 m, 70–190 m above the land, with trees on top (added to `TreeField` via `SetFixedTrees` when `IslandField.Version` changes). `EdgeRadius`/`TopHeight` define the top and are shared by `IslandRenderer` (meshes built on the thread pool: a tube of rings from the domed top down the rocky underside, smooth normals, hanging emissive crystals via `MeshBuilder`) and by `GroundBelow`, which `Ground` (src/World/Ground.cs) combines with the terrain so the player can land on islands. Islands are drawn with the object shader (identity model matrix) and cast shadows. The underside's wobble grows in below the lip, so the rock never juts out past the top's edge.

**Waterfalls and ponds.** An island's layout (position, size, shape rolls and waterfalls: `IslandField.Site`) is a pure function of the seed and cell, apart from its height; a few (`FallChance`, some of them two: `TwoFallsChance`) have a waterfall, a thin silvery rivulet `FallMinWidth`..`FallMaxWidth` wide, landing `FallReach` past the edge (`FallFoot`). `TerrainField` (same seed as the islands!) reads the sites to dig a broad basin (`PondMinRadius` + `PondPerWidth` × width) where a fall lands on land that can hold one (dry, and flat enough that the bank is no tall dam) (`Ponds`: basin under the water, a bank half a layer above it, a slope back to the land; `PondAt`/`InPond`). Rule: a waterfall always ends in a basin, so `IslandField.Generate` drops the falls whose foot has none; grass, trees, decorations and crystals skip the ponds. `Island.Falls` holds each fall's lip, direction, width, bottom and pond radius. `WaterfallRenderer` builds one mesh for all falls when `IslandField.Version` changes (a trickle across the island top, three thin round threads arcing off the lip and parting as they fall, the pond disc, a vapour ribbon) and draws it after the sea with premultiplied-alpha blending, no depth writes and no culling; one shader, switched per vertex by a kind attribute. The vapour is a ribbon down the fall that the vertex shader turns to face the camera (so it has no edges), with drifting wisps, billowing out over the last 30 m. The basin is foamy: a boiling white core where the water lands, patches of bubbles carried outward (two flow phases cross-faded, flow-map style, so the drift never stretches), foam on the ring crests and along the bank. Butterflies never spawn in a basin and fly over its water (`Creatures.Surface`). Threads carry their cross-section centre and half-width, so the vertex shader widens far ones to ~1.5 px (dimming them to match) instead of letting them flicker away. The threads read as flowing liquid: sawtooth pulses and fine streaks race down over darker water (the pattern evens out on far, widened threads). Splashes: for the `MaxSplashes` falls nearest the player within `SplashRange`, `DropsPerFall` additive point sprites with no vertex data (like the motes), each deriving a ballistic arc (droplet) or a slow rising puff from its index and the time, the feet passed as a `uFeet` uniform array. Each pond adds a point light (`WaterfallRenderer.Lights`).

**Creatures (`Creatures`, `CreatureRenderer`).** Surface fish have a silvery body and coloured fins (a dorsal sail, fluttering side fins, a keel fin, a long forked tail): the mesh colour channel marks body (1,0,0) or fin (0,1,tip), and the vertex shader picks one fin colour per fish from its phase (red, violet, yellow, orange, cyan, magenta). Butterflies and fish respawn around the player; `Update` takes the `Atmosphere`: butterflies go from `DayButterflies` (30) by day to `ButterflyCount` (90) at night (extras are simply not respawned). Fish spawn only in open water (at least `FishSpawnDepth` deep, with water `FishMinDepth` deep for `FishSpawnClearance` metres all around); each keeps to a minimum depth (`FishMinDepth`, or `BraveFishMinDepth` for one in `BraveFishEvery`): when the water 5 m ahead gets shallower it turns toward the nearest heading that stays deep (`TryDeepHeading`), and despawns if it finds none or ends up in water half that depth. Deep fish (`CreatureKind.DeepFish`, bigger deep-bodied mesh with fins and glowing flank spots, one of four glows per school via the phase band of 20) swim in `DeepSchools` (3) schools of 3–6 within `DeepRange`, born only where the water is `DeepSpawnDepth` deep and stays `DeepMinDepth` deep for `DeepClearance` metres all around (`AcceptSchool`), at least `SchoolSpacing` apart (they also steer away from each other). A school is a point that roams at its own level (the whole school kept clear of bottom and surface), meandering and turning at a limited `TurnRate` away from other schools and toward deep water (probing 12 m ahead and both flanks, `TryDeepHeading` with a longer reach). Its fish are not a rigid formation (that made them move in lockstep): each is its own swimmer with a heading that turns at most 1 rad/s, a pace between 40% and 180% of the school's, and its own lag (`_deepResponse`), easing toward a slowly drifting place (`SchoolTarget`, slots at least `MinGap` fish lengths apart from `SchoolSlot`), steering away from and, if needed, nudged apart from its neighbours. Seven bird flocks of different sizes (2 to 12) fill the day sky; as the sun sinks below ~21° (sun Y 0.36 → 0.2, i.e. from the late afternoon into the evening twilight) they leave, until only `NightFlocks` (1: the first flock, a pair) stays through the evening and night: each flock has an eased `Presence` that widens its orbit out to `FlockAwayDistance` and hides it, so flocks fly in and out instead of popping. Flocks are never neat (no files or lines): ragged, lopsided Vs with uneven arms, gaps and stragglers, clouds, two or three knots drifting apart and together, and swirling balls; each bird has its own random spot and quirks (`_birdSlots`, `_birdQuirks`), wanders around it at its own pace, and every flock slowly stretches and squeezes. Flocks of different spacing, height and orbit direction wheel around an anchor that follows the player, each bird drifting around its slot. Flock altitude follows `SmoothHeight`, eased, never the layered tiles (their steps made flocks jump).

**Snow (`Weather`, `SnowRenderer`).** Key 3 toggles snow (rain and snow stop each other); `Weather.Snow` eases like the rain, and `Weather.SnowCover` grows while it snows (full in ~75 s) and melts afterwards (~3 min, faster in rain); both go out with the sky uniforms (`uSnow`, `uSnowCover`). `snowOn(pos, up)` in `SkyRenderer.Glsl` says how much snow lies on a surface: a snow line that starts on the heights and creeps down to the shores as the cover grows, only on up-facing surfaces, in noise drifts; the terrain, grass, tree and object fragment shaders mix their albedo toward `SnowColor` with it (not emissive parts). Snow closes the clouds and turns the sky pale blue-grey; `PostProcess.Finish(night, cold)` drains colour toward a cold blue-grey. `SnowRenderer`: 9000 point-sprite flakes, no vertex data, drifting and swaying in a box round the camera, premultiplied blending. `MINE_SNOW=1` starts with the snow already lying. Pressing 3 twice within `WeatherDoubleTap` (0.4 s) starts a blizzard (`Weather.Blizzard` → `uBlizzard`): up to 22000 flakes (`SnowRenderer` draws a share of its `Count`), larger and blown nearly sideways, the snow settling twice as fast, pale clouds and sky, and a whiteout in `finishColor` that hides the distance within tens of metres (`MINE_BLIZZARD=1`).

**Storms.** Pressing 2 twice quickly starts a storm (`Weather.Storm` → `uStorm`): up to 36000 faster, wind-slanted drops, a darker sky, and lightning every 3–12 s (`Weather.Lightning`, a double flash; `LightningAzimuth`/`LightningSeed` → `uLightningBolt`): the sky, the clouds (`marchClouds`) and the world ambient light up, and `lightningBolt` draws a jagged bolt from the clouds to the horizon (`MINE_STORM=1`). Auroras hide in storms and blizzards.

**Rain (`Weather`, `RainRenderer`).** Key 2 toggles rain; `Weather.Rain` eases in (~8 s) and out (~12 s) and is published as `SkyRenderer.Rain` → `uRain` with the sky uniforms. It lowers the cloud coverage threshold (overcast, and more cloud shadow), dims the sky toward a glowing indigo, veils the sunlight (×0.55) and thickens the mist (×3.5), hides most motes, and on the water adds ring ripples (`rainRings`, one layer of cells, computed once per pixel for both the normal and the glow) that bend the normal and glow faintly. `RainRenderer` draws 20000 drops with no vertex data (like the motes): very thin camera-facing quads along a slanted fall in a box following the camera, additive, faint uncoloured silver (the user did not want coloured rain), never thinner than ~0.7 px (fainter instead, so they do not flicker); drops appear one by one as the rain thickens; not drawn under water. Keep the magic, cosmic tone in the sky and water (no dull greys), but the drops themselves stay colourless.

**Motes (`MoteRenderer`).** 1800 additive point sprites with no vertex data: each derives position, drift and colour from `gl_VertexID`, wrapped in a box that follows the camera; golden sparkles by day, lilac spores at dusk, blinking fireflies at night, fading out when flying high.

**Decorations.** `TreeModels.Decoration` (violet and cyan crystal clusters, lotus flowers, glow bells, palms in three builds (`Palm`, `TallPalm` 13 m and deeply curved, `ShortPalm` 4.6 m and stocky, picked by `TreeField.RandomPalm` with instance scales 0.7–1.35 so no two match), reed clumps, and flowers: daisies (as short as the tulips), tulips (glowing cups on short stems of very different heights, stems 0.08–0.33 m and an instance scale of 0.9–1.15 (`AddFlowers`), so they stay below the knee, about half a metre at most: taller ones were too tall, each a blend of two of eight hues at its own brightness, a heart of a deeper shade), glowing starflowers (as short as the tulips), lupins with glowing tips, all bare stems (the glow bells and the lupins are final, approved by the user; the stem of a bell turns upright under it and ends inside the cone); and flowers born of light built by `LeafyFlowers` (colours from `PaletteOf`): pale glowing stems (`GlowTube`) with tinted leaves along them (phyllotaxis) whose midribs glow (`ribGlow`), each stem crowned by a flower and branching near the top into 2–3 curved side stems with smaller flowers or buds (a bract at each fork), a calyx, heads (`Head`) of curved cupped neon petals (`Petals`) glowing toward the tips, shining stamens, floating seeds of light, the odd closed bud; leaves, petals and sepals are all `Blade` surfaces (curving in one plane, folded, pointed or rounded): violet irises with sword-leaf fans, magenta poppies on leaf rosettes, cyan lilies with recurved petals. Each kind also casts a coloured light (`TreeModels.FlowerLight`): `TreeField.FlowerLights` returns the nearest 8 within 14 m, faded toward a cutoff that follows the distance of the first one left out so lights never pop, merged with the crystals' lights in `CollectLights`; flowers are scaled up (instance scale over 1) to stand above the grass) are extra variants after the tree styles, drawn by the same instanced `TreeRenderer` (so they get wind, shadows, emissive glow and levels of detail). `TreeModels.MaxDistance` hides small plants sooner; `TrunkRadius` 0 means no collision; `CastsShadow` keeps small flowers out of the shadow map. `TreeField.AddDecorations` samples 20 points per cell and decorates by ground type: lotus on the shallows (at the water level), palms on the shores, glow bells in noise patches on meadows; giant crystal clusters are no longer generated (removed: glass and crystal come from veins in the rock spires; the models remain). Their base is a dark angular plinth (`TreeModels.Plinth`: flat faces, standing on the ground, never sunk; nothing round in this world). `TreeField.AddFlowers` samples 40 more points per cell: in meadows, everywhere in moderation (a little thicker in patches), one kind dominating each area with others mixed in; under the woods (same forest noise as the trees), starflowers and bells. Each biome has its meadow flowers (indigo: lupins, starflowers; pink: tulips, daisies; turquoise: starflowers, daisies; deserts: the odd starflower), the dominant one from bands of a species noise. The flowers born of light grow only in `TreeField.AddLightGardens` (45 samples per cell): gardens only under the woods, where a garden noise is positive, densest at their heart and where the forest noise is highest (thick woods); the biome picks the kind (irises indigo, poppies pink, lilies turquoise), none in deserts. `TreeField.AddPalmGroves` (30 samples per cell) gathers palms in groves where a grove noise is high, thickest up to 3 m above the water and thinning out by 12 m (a few inland). `TreeField.AddReeds` scatters reed clumps (round stems with bulrush heads; instance scale low, middling or towering) over some tiles of the reed beds (`GroundMaterials.Reeds`) from 1.2 m under to 1 m over the water. Crystal clusters within 80 m also become point lights (`TreeField.GlowingLights`, merged with the objects' lights by distance in `WorldObjects.CollectLights`). The bloom prefilter uses a Karis average so lone super-bright pixels (e.g. glints through pixel cracks) do not bloom into blobs.

**Objects and lights.** `WorldObjects` (src/World/WorldObjects.cs) holds the collectable objects (the generator scatters none any more: the small glowing crystals were removed from the world; the kind remains) (`ObjectKind.Crystal`): generated ones (deterministic per 64 m cell, within `ActiveRadius`, only on gentle ground; positive ids, picked-up ids remembered in `_taken` so they never respawn) and placed ones (negative ids). `ObjectDefs` gives each kind its name, light colour/intensity/radius/height and pick capsule. `Pick` finds the object whose vertical capsule the view ray passes nearest along the ray; `TerrainField.Raycast` (march + bisection) finds where to place. Left click picks up the aimed object into the inventory, right click places a crystal on the aimed ground within `ReachDistance`. `CollectLights` returns the `MaxPointLights` (16) nearest lights with the crystals' slow pulse, uploaded as uniform arrays each frame; point lights are dimmed in daylight. `ObjectRenderer` builds one flat-shaded procedural mesh per kind (position, normal, colour, emissive) drawn per object with a model matrix; emissive parts glow and cut through haze, the aimed object is highlighted. Objects cast sun shadows via `ShadowMap.SetCasterModel`.

**Lighting and sky.** `DayCycle` (src/World/DayCycle.cs) holds the time of day (0 = midnight, 0.5 = noon; 20-minute cycles; the game starts at 8:00) and interpolates colour keyframes (night, dawn, twilight, day, noon, dusk: all violet/pink, noon clearer and bluer) into an `Atmosphere`. The sun circles low for long twilights, then climbs for a short bright noon: its elevation is `SunMid + SunSwing * w + SunPeak * w⁴` (w = sin(azimuth), the last term only when positive), peaking at ~54° and above 30° for about a sixth of the cycle; a high sun's light is up to 35% stronger; the moon (drawn as a giant crescent planet, `PlanetSize` ≈ 20° radius, lit mostly from behind with a glowing lilac-magenta limb and faint glowing cracks, two small moons beside it; `planetSurface`, `moonHalo`) rides opposite and high at night; auroras (`aurora`: curtains of rays over a few noise-chosen stretches of the horizon, cyan foot, blue, magenta tips) hang in front of the sky bodies at night; night clouds are lit magenta; the galaxy direction drifts slowly, always well above the horizon, with `GalaxyGlow` rising at night. The sky shader adds the galaxy (five log-spiral arms of uneven strength (`armIndex`, changing in the dark lanes), bent asymmetrically by a broad sky noise and made wavy and clumpy by the cloud noise, with spurs between them, dark dust lanes, cyan clouds, a gentle core and bulge the arms emerge from, spherical rim, star dust), nebula veils (cloud noise), denser stars and shooting stars (`shootingStar`/`streak`: one 9 s slot in two, gliding 40–90° along a great circle in 3–4.5 s, the tail (17–31°) measured along the circle, fading out over the second half; key 1 launches one across the view for debugging via `SkyRenderer.LaunchShootingStar`, visible by day too). Shooting stars burn up in the atmosphere, so they are added last, in front of the moon, galaxy and nebulae (clouds still hide them). The terrain has a few twinkling glitter grains (thickest on sand), each with its own pace and phase from hashes other than the one that picks the cells (from the same hash, all visible grains blinked together). `SkyRenderer` draws the sky as a full-screen triangle (gradient with a warm sun-side horizon, small square sun, round moon, twinkling stars, a cloud layer moved by `DayCycle.Elapsed`). Warm `Day` keyframes lead from the twilights into the `Noon` keyframe (0.47–0.53). `SkyAngle` (stars, nebulae, galaxy drift) comes from `Elapsed`, not `TimeOfDay`, so it never jumps at midnight. The galaxy is dramatic but soft (broad arms, noise via coarse mips, soft lanes, wide rim); keep the arm count a whole number (no seam) and measured by angle from its centre (rim at ~68°), so it never fits on screen; its streak noise is sampled through cos/sin of the swirl to avoid a seam. Its `Glsl` constant (sky uniforms, `skyColor()`, `toneMap()`, `hash13()`) is pasted into both the sky and the terrain fragment shader, so fog takes the exact sky colour in the view direction. The terrain adds a soft aerial haze that tints distance with the hue of the sky while keeping brightness (no whitening), a far veil toward the sky colour from 300 m (`uVeil` 0.85 at the view's end, `uVeilStart`; `uVeilHeight` > 0 would make it lie low: tried, the user chose the plain one), and an edge fog to the sky colour over the last quarter of the view distance.

**Shadows (`ShadowMap`).** Each frame the caller's `drawCasters` draws the geometry around the player into a 2048² depth texture from the light direction, with an orthographic box of half-width `Radius` (150 m) centred on the player and snapped to texels. The light direction follows the sun every frame, so shadows move smoothly (it used to follow in steps of ~0.25°, which with a low sun made a tall tree's shadow tip jump by metres). To keep edges from crawling as the view turns, the light view turns about a pivot near the player snapped to `PivotCell` (32 m), not about the world origin: the texel grid then drifts over the nearby world by only hundredths of a texel per frame. Tree leaves' quick shiver is left out of the shadow pass (`treeWorld(..., shiver: 0)`), which made shadows flicker. The pass stores the faces turned toward the light (back faces culled as usual) with polygon offset; together with a normal offset and a tiny bias in the shader this avoids acne while keeping shadows attached. The terrain shader samples it as `sampler2DShadow` (texture unit 0, 3×3 PCF) for direct light only.

**Player.** The player is `Height` (2 m) tall, the eye `EyeHeight` (1.8 m) above the feet (`SneakEyeHeight` 1.45 m), so the view clears ordinary grass (up to 1.45 m); The game starts in the heart of the prairie nearest the origin (`FindSpawn`; `MINE_POS` overrides it; `Game.Spawn` (-517, 128) only places `MINE_DEMO`'s house). `Player.Position` is the feet. It walks on `Ground.Height` (terrain tiles and island tops): walls up to `StepHeight` (one layer) are climbed by walking and steps down up to `GroundSnap` (two layers) are followed, the camera easing both ways via `_stepOffset`; for `GroundGrace` after leaving the ground the player still counts as grounded for climbing, so stepping between layers never stutters;, higher ones block horizontal motion (probed `Radius` ahead) unless the feet are already above them (jumping clears ~1.2 m); `GroundSnap` follows steps down. A step up is measured from the feet before the frame's fall (`startY` in `Move`): measured after it, a long frame (gravity sinks the feet several cm) eased the camera up like a step, a visible jolt while standing still. On the Windows laptop (RTX 2060 rendering, Intel UHD showing at 59 Hz) vsync stalls a frame for ~55 ms every 10–40 s inside the driver (the passes' GPU times and the CPU stay normal; with `MINE_NO_VSYNC=1` there is none). Below `WaterLevel - SwimDepth` the player swims: 3D movement like flying but slow with heavy drag (`SwimSpeed`, `SwimAccel`, `SwimDrag`), Space/Shift up/down, idle buoyancy toward `FloatDepth`, ledges up to `SwimClimb` can be climbed out onto. Under water, world shaders (`uUnderwater` in `finishColor`) fade into an indigo murk, the water surface is shaded as seen from below and the sky shader outputs the murk. Movement has inertia (exponential approach), double-tap W to sprint, Shift to sneak (slower, lower camera), F to fly, T to speed up time, 1 to launch a shooting star (debug), 2 to toggle the rain.

**Math conventions.** `System.Numerics` matrices (row-vector convention) are uploaded untransposed, and shaders compute `uViewProj * vec4(pos, 1)`. So on the C# side the combined matrix is `view * projection`. Its projections map depth to [0, 1] in NDC, which GL then maps to window depth [0.5, 1]; `ShadowMap.DepthBias` accounts for that.

Namespace gotcha: `Silk.NET.OpenGL` also defines `Shader`. Files outside `Mine.Rendering` that import it need `using Shader = Mine.Rendering.Shader;`.
