# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

An exploration game with smooth, dreamlike landscapes (inspired by Journey, Stray, Genshin Impact), in C# / .NET 10 using Silk.NET 2.23 (windowing, input, OpenGL). It started as a Minecraft clone: the block-based version lives on `main` (and `vegetazione-blocchi` adds swaying grass to it); this branch (`terreno-realistico`) replaces the blocks with a continuous terrain. Targets Windows, Linux and macOS, so portability matters: keep the GL context at **3.3 core + forward-compatible** (macOS caps at 4.1) and avoid platform-specific APIs. The user communicates in Italian; in-game UI strings (window title HUD) and README are in Italian.

Roadmap on this branch: 1) smooth terrain (done), 2) objects the player can pick up and place with point lights (done; for now only small glowing crystals, lanterns and torches were removed pending a redesign), 3) instanced grass and procedural trees swaying in the wind (done), 4) post-processing (bloom, light shafts, grading), volumetric clouds, surreal elements (done). Then the **cosmic direction**, modelled on AI "cosmic purple beach" art the user shared: a violet/indigo/magenta world with cyan accents, a giant spiral galaxy, bioluminescence everywhere, dark silhouettes. The day/night cycle stays, but its brightest moment is a twilight. Phases: A) sky, palette and cycle (done), B) water with sky reflections and a bioluminescent shore (done), C) giant crystal clusters and glowing flowers (done), D) crystal stepping-stone paths (tried, removed: the stones could not be climbed), E) creatures (butterflies, birds, fish) and palms (done).

## Commands

```
dotnet build                 # debug build
dotnet run -c Release        # play
dotnet publish -c Release -r <win-x64|linux-x64|osx-arm64> --self-contained -p:PublishSingleFile=true
```

The game starts full screen at the monitor's own resolution (no display mode change; `Game.SetFullscreen`), F11 or Alt+Enter toggles a 1280×720 window, F10 moves the game to the next monitor (`NextMonitor`), and `MINE_WINDOWED=1` starts windowed. `GpuPreference` (src/GpuPreference.cs) sets the Windows per-app "High performance" GPU preference for the running exe at startup and, the first time, restarts the game once so the discrete GPU is used.

There are no tests and no linter. The SDK lives at `C:\Program Files\dotnet\dotnet.exe`; if `dotnet` is not on PATH in the current shell, call it by full path. To verify rendering changes, launch `bin\Debug\net10.0\Mine.exe`, screenshot its window and kill the process (the game captures the mouse in raw mode while focused). Where screenshots are not possible (macOS without screen-recording permission), at least launch it for ~10 s to catch shader compile errors (they throw at startup), and measure with the debug environment variables: `MINE_FPS_LOG=1` prints the HUD line (with FPS) to the console every half second, `MINE_RAIN=1` starts with rain, `MINE_TIME=0.9` sets the time of day, `MINE_PITCH=0.3` the view pitch (radians), `MINE_YAW=3.14` the heading, `MINE_POS=600,840` spawns exactly there (in water the player floats up), `MINE_NO_VSYNC=1` uncaps the frame rate (use it when measuring), `MINE_SKIP=sky,grass,...` skips passes (shadow, terrain, grass, trees, sky, water, post) and `MINE_GPU_PROFILE=1` prints the GPU time of each pass (`GpuProfiler`, timer queries; on Apple GPUs they overstate, so compare FPS with passes skipped instead). A window can be captured on macOS with `screencapture -l<window id>` (id from `CGWindowListCopyWindowInfo`). On a MacBook Air M1 (Retina, 2560×1440 rendered) the game runs at ~62–67 FPS uncapped in the open and ~55–57 in the thickest woods (tree pixels use the full lighting): the cloud ray march (~2.7 ms at half resolution), terrain and grass shading, point lights (~1.6 ms at night) and post (~2.5 ms) are the main costs; moving grass lighting to the vertex shader was tried and was much slower (millions of blade vertices).

## Architecture

`Game` (src/Game.cs) owns the window, input callbacks, the inventory and the world shaders, and drives the loop: `Player.Update` → `DayCycle.Update` → `TreeField.Update` (+ trunk collision) → `TerrainRenderer.Update` → `TreeRenderer.Update` → `GrassRenderer.Update` → `WorldObjects.Update` (+ aim), then collect point lights → render shadow map (terrain + trees + islands + objects) → `PostProcess.BeginScene` (HDR buffer) → terrain → grass (culling off) → trees → objects → islands → sky (last, see below) → motes → `PostProcess.Finish` (bloom, grading to the screen) → crosshair. All scene shaders output linear HDR; tone mapping lives only in the composite pass. The window title is the HUD. Units are metres; Y is up.

**Terrain shape (`TerrainField`).** The land is layered: square tiles of `TileSize` (2 m), each flat at a multiple of `LayerHeight` (0.5 m), with vertical walls between. `SmoothHeight(x, z)` is the continuous surface they are cut from (2D `PerlinNoise`: continental swells, domain-warped hills, round-crested dune ridges, detail, rare rock spires; slopes are kept gentle so ~99.5% of neighbouring land tiles differ by at most one layer (walkable), larger steps being rare; deserts (see Biomes) have gentler hills and taller dunes; `Lakes` scoops at most one lake per `LakeCell` (400 m, `LakeChance`) on low and middling land (not where the continent noise is high): a wobbly shore `LakeMinRadius`–`LakeMaxRadius` across, banks sinking gently over `LakeBank` to just under the water, a floor `LakeMinDepth`–`LakeMaxDepth` lower toward the middle; below `WaterLevel` the land drops `DepthScale` times faster, so shores stay gentle and the water gets deep (about 20% of the land is water, ~160 lakes over 2 ha per 64 km², most over 12 m deep). `Height(x, z)` = `TileHeight` = the smooth height at the tile centre snapped with `Layer`. `Normal` is the smooth surface's normal (used for "how steep", e.g. where trees and crystals may grow). `InsideTile`/`TileCenter` keep things placed on a tile's flat top. Pure and thread-safe; no stored terrain data.

**Terrain rendering (`TerrainRenderer`).** Chunks of 64 m out to `ViewDistance` (1300 m). Each chunk is a grid of flat blocks (terrain tiles near the camera, merged 2×2, 4×4… farther away per `LodSteps`/`LodRanges`, each merged block at the layered height of its centre) plus vertical walls where neighbouring blocks differ; walls on the chunk border reach deeper (skirts) to hide cracks against other levels of detail. Non-indexed triangles, vertex layout position, normal, slope (smooth normal.y: picks the material, 0 on walls → rock), ao (walls darker at the foot). Meshes are built on background worker threads fed by a `BlockingCollection`, nearest first, and uploaded on the main thread at most `UploadsPerFrame` per frame; a chunk keeps drawing its previous mesh until the new one arrives, and stale results are dropped. `Draw` skips tiles well behind the camera; `DrawNear` draws only the tiles around a point for the shadow map.

**World shaders (`TerrainShaders`).** Terrain and object shaders share the private `Lighting` GLSL (pasted after `SkyRenderer.Glsl`): `litColor` = albedo × (generous ambient mixing the keyframe ambient with the sky colour around the normal + Lambert sunlight × shadow map + point lights), and `finishColor` = aerial haze + light halos + edge fog + tone map. Point lights skip pixels beyond their radius, and halos skip lights whose ray passes over 8 m away (lowered by their value there so they still fade to zero): both loops run over up to 16 lights per pixel and were a large share of the frame. Terrain materials are procedural, from slope and height: grass (drifting between green, golden and a teal accent), warm sandstone with faint wavy strata on steep slopes, pale sand in the lowlands, plus grain that fades with distance.

**Shared GLSL.** `SkyRenderer.Hash` (`hash13`, any stage) and `SkyRenderer.Glsl` (sky; fragment only, it uses `fwidth`). In `TerrainShaders`: `Wind` (`windOffset`), `TreeTransform` (`treeWorld`, used by both the tree shader and the shadow pass), `Materials` (noise, `grassColor`, `rockSand`), `Lighting`. Defining `CHEAP` before `Lighting` (grass) uses one shadow tap, no haze noise and no halos. `GroundMaterials` (src/World) is a C# mirror of `grassColor`/`rockSand` so grass is coloured and culled on the CPU: keep the two in sync.

**Biomes (`GroundMaterials.Biome`).** Four biomes from large-scale value noise, computed identically in C# (`Biome`, `Desert`) and GLSL (`biomeWeights`, `desertWeight` in `Materials`): indigo woods, pink woods, turquoise woods (bands of a "flavour" noise) and deserts (~17% of the land), weights summing to 1 with borders a few tens of metres wide. Each biome pulls the grass patches 40% toward its hue (the five-hue patch mix stays), so ground and blades agree; deserts are covered in warm peach sand with faint ripples (`rockSand`/`GrassWeight` count it as sand: no grass). `TreeField.PickBiome` draws a biome by the weights at each point, so trees and flowers of neighbouring biomes mingle across borders.

**Grass (`GrassRenderer`).** 32 m tiles within `Radius` (70 m), built on the thread pool: blades grouped in tufts (`MinTuft`–`MaxTuft` blades sharing one root within a few cm, each facing its own way around the tuft and leaning out, outer ones shorter and bent more, all sharing the thinning key so tufts thin out whole), tufts crowded in clumps (up to `MaxTuftsPerClump` within `ClumpRadius`, clamped to the terrain tile's flat top), some tufts short and spreading (`CarpetMin`–`CarpetMax`, fewer in tall meadows) to carpet the ground, at `BladesPerSquareMetre` (42; a little more in tall meadows) with heights interpolated from a 1 m grid, kept only where `GroundMaterials.GrassWeight` says grass, and uploaded as one instance buffer per tile (root, bend, facing, height, thinning key, colour variation, ground colour). Grass colour comes in patches of one hue (teal, violet, magenta, lilac gold, sky blue: `grassColor`/`GrassColor`, kept in sync). No blades grow below 1 m over the water: the shores hold reed clumps instead (see Decorations). Blade height is `MinHeight` plus a random share of a maximum that grows in the tall grass meadows (`GroundMaterials.TallGrass`: thigh-high, and over head height in their hearts; taller blades are broader). Each blade is a shared 7-vertex triangle strip shaped in the vertex shader, which thins blades out with distance (survivors get wider; each tile's blades are sorted by thinning key and `Draw` issues only the prefix that can survive at the tile's nearest point, the same formula as the shader: keep them in sync) and sways the tips with the wind. Blades are lit with a wrapped diffuse, a normal turned toward the camera horizontally only, and backlight when looking toward the sun.

**Trees.** `TreeField` (src/World) places trees per 32 m cell on the thread pool, within `Radius` (950 m): thick where a forest noise is above `WoodsThreshold` (8 to ~20 canopy trees per cell plus half as many shrubs and saplings as undergrowth), the odd lone tree elsewhere, sparse groves of dry trees in the deserts, only on gentle ground above the sand and never in tall grass meadows; the biome picks the family (`Canopy`, `Undergrowth`), and within it each grove (Voronoi regions around points jittered on an 80 m grid, `GroveSpecies`) is dominated by one species, with `OtherSpeciesChance` of another. `ResolveCollision` pushes the player out of trunks. `TreeModels` builds 16 procedural styles (incl. a 15 m giant, a weeping willow, a tiered pine, a sapling, a shrub, and three bare dry ones for the deserts: `Bare` styles have no foliage, their branches forking twice into twigs via `AddTwigs`, and far away keep only the thicker branches) (tapering curved trunk, branches, crowns of noise-displaced ellipsoid blobs; two with glowing orbs) at 4 levels of detail from the same random structure, the last one a single-ellipsoid silhouette. Vertex layout: position, normal, colour, emissive, sway (0 at the trunk foot, 1 on leaves). `TreeRenderer` draws one instanced batch per variant and level (instances: position, yaw, scale), re-sorting into levels when the tree set changes or the camera moves 8 m; each batch's instances are grouped into the near ones (40 m) and 16 direction slices, and `Draw` skips the slices out of view (runs of visible slices are drawn by pointing the instance attributes at their first instance, GL 3.3 having no base instance); levels 0–1 (within 170 m) also cast shadows through the shadow map's instanced path (`SetInstanced`).

**Post-processing (`PostProcess`).** The scene renders into an RGBA16F colour + 24-bit depth texture framebuffer (at 70% resolution in low quality). Bloom: 13-tap downsample chain over 6 half-size levels (the first with a soft threshold, `BloomThreshold`), tent-filter upsample added back with additive blending. (Screen-space light shafts were removed: their radial blur stamped rows of blobs.) The bloom prefilter and the composite turn NaN/inf pixels black and cap the rest, since some GPUs produce NaNs where others do not (keep GLSL `pow` bases non-negative for the same reason). Composite: scene + bloom + shafts, exposure, the soft-shoulder tone map, saturation, split toning, vignette, dither.

**Sky and clouds.** The sky is drawn after the opaque geometry, at the far plane with `DepthFunc(Lequal)` and no depth writes, so its cost is paid only on visible sky pixels. The cloud ray march runs before it in its own pass (`SkyRenderer.DrawClouds`) at half resolution into an RGBA16F texture (scattered light, transmittance), skipping texels whose 4×4 full-resolution footprint in the water snapshot's depth holds no sky; the sky shader samples it bilinearly (unit `CloudsUnit`). This took ~45 to ~56 FPS on an M1 with no visible change. The moon (`moonSurface`) is a lit sphere, not pixelated: pale lilac silver, violet seas and grain from the cloud noise, `moonCraters` at two scales (bowls shaded from the light side, raised rims), a fixed gibbous phase with a soft terminator and a faintly glowing dark side, limb darkening, kept well below white (bright values washed out its texture), softly edged and veiled 30% toward the sky colour so it sits in the sky; `moonHalo` adds a corona, a wide halo and a faint ice ring. Its disk is opaque: nebulae, galaxy and stars are masked behind it. At night the clouds are darker masses (ambient × 0.55) with bright moonlit silver edges, galaxy-tinted tops (lightning flashes were tried and removed: the user did not like them). Clouds are ray-marched through a slab (`CloudBottom`–`CloudTop`, 260–760 m; a very broad noise raises or lowers the coverage threshold, opening clear skies between banks of towering clouds with dark bellies and bright rims) in `SkyRenderer`: `cloudDensity` samples `CloudNoise` (a tileable 64³ R8 texture generated at startup, bound to unit `SkyRenderer.CloudNoiseUnit`), blurred via `textureLod` as steps grow; each sample marches a few steps toward the light for self-shadowing (32 steps in high quality; the coverage threshold, `cloudThreshold`, is read once per step and reused by its light samples, and a step far outside any cloud (`cloudDensityRaw` < -1.2) makes the march skip the next one), with a two-lobe Henyey-Greenstein phase (silver lining) and interleaved-gradient-noise jitter. `cloudDensity` is part of `SkyRenderer.Glsl`, so the world shaders use it for moving cloud shadows (`cloudShadow` in `Lighting`). Quality: `SkyRenderer.LowQuality`/`PostProcess.LowQuality` (fewer cloud and shaft samples, lower render scale), chosen at startup from the GL renderer string (Intel/llvmpipe → low) and toggled with Q.

**Waves.** The water shader draws breaking waves along the depth contours of the smooth sea floor: `SeaFloorMap` (unit 6) holds `TerrainField.SmoothHeight` over 512 m round the camera (256², built on the thread pool when the camera moves 64 m), because depths read from the layered tiles would make the wave fronts blocky. Bands of phase `depth / 1.6 + time` roll shoreward, rear up below 7 m, break into bubbly pink-white foam (trailing behind the crest) below ~3 m, with a cyan glow on the rising face; each wave varies in strength along its length.

**Water.** `TerrainField.WaterLevel` (15 m) is the sea and lake level; sand covers the shores just above it (keep `rockSand` in the shader and `GroundMaterials` in sync), trees stay 5 m above it, grass 1 m. `WaterRenderer` draws one quad at that level following the camera (culling off); the terrain hides it wherever it rises above. Before the water, `PostProcess.SnapshotForWater` blits the scene colour and depth into copies (units 3 and 4) so `TerrainShaders.WaterFragment` can refract the bottom (bent by ripples, absorbed toward deep indigo with the view-space thickness, from linearized depths) and reflect `skyColor(r, true)` with Fresnel, plus a glint path toward the light and bioluminescence (ridged-noise veins pulsing in the shallows, a glowing line at the shore, sparkles). `Ground` keeps the player's feet at most `WadeDepth` below the surface. Order: opaque → snapshot → clouds (half resolution) → sky → water → motes.

**Floating islands.** `IslandField` (src/World) places at most one island per 420 m cell within 1700 m, 70–190 m above the land, with trees on top (added to `TreeField` via `SetFixedTrees` when `IslandField.Version` changes). `EdgeRadius`/`TopHeight` define the top and are shared by `IslandRenderer` (meshes built on the thread pool: a tube of rings from the domed top down the rocky underside, smooth normals, hanging emissive crystals via `MeshBuilder`) and by `GroundBelow`, which `Ground` (src/World/Ground.cs) combines with the terrain so the player can land on islands. Islands are drawn with the object shader (identity model matrix) and cast shadows. The underside's wobble grows in below the lip, so the rock never juts out past the top's edge.

**Waterfalls and ponds.** An island's layout (position, size, shape rolls and waterfalls: `IslandField.Site`) is a pure function of the seed and cell, apart from its height; a few (`FallChance`, some of them two: `TwoFallsChance`) have a waterfall, a thin silvery rivulet `FallMinWidth`..`FallMaxWidth` wide, landing `FallReach` past the edge (`FallFoot`). `TerrainField` (same seed as the islands!) reads the sites to dig a broad basin (`PondMinRadius` + `PondPerWidth` × width) where a fall lands on land that can hold one (dry, and flat enough that the bank is no tall dam) (`Ponds`: basin under the water, a bank half a layer above it, a slope back to the land; `PondAt`/`InPond`). Rule: a waterfall always ends in a basin, so `IslandField.Generate` drops the falls whose foot has none; grass, trees, decorations and crystals skip the ponds. `Island.Falls` holds each fall's lip, direction, width, bottom and pond radius. `WaterfallRenderer` builds one mesh for all falls when `IslandField.Version` changes (a trickle across the island top, three thin round threads arcing off the lip and parting as they fall, the pond disc, a vapour ribbon) and draws it after the sea with premultiplied-alpha blending, no depth writes and no culling; one shader, switched per vertex by a kind attribute. The vapour is a ribbon down the fall that the vertex shader turns to face the camera (so it has no edges), with drifting wisps, billowing out over the last 30 m. The basin is foamy: a boiling white core where the water lands, patches of bubbles carried outward (two flow phases cross-faded, flow-map style, so the drift never stretches), foam on the ring crests and along the bank. Butterflies never spawn in a basin and fly over its water (`Creatures.Surface`). Threads carry their cross-section centre and half-width, so the vertex shader widens far ones to ~1.5 px (dimming them to match) instead of letting them flicker away. The threads read as flowing liquid: sawtooth pulses and fine streaks race down over darker water (the pattern evens out on far, widened threads). Splashes: for the `MaxSplashes` falls nearest the player within `SplashRange`, `DropsPerFall` additive point sprites with no vertex data (like the motes), each deriving a ballistic arc (droplet) or a slow rising puff from its index and the time, the feet passed as a `uFeet` uniform array. Each pond adds a point light (`WaterfallRenderer.Lights`).

**Creatures (`Creatures`, `CreatureRenderer`).** Surface fish have a silvery body and coloured fins (a dorsal sail, fluttering side fins, a keel fin, a long forked tail): the mesh colour channel marks body (1,0,0) or fin (0,1,tip), and the vertex shader picks one fin colour per fish from its phase (red, violet, yellow, orange, cyan, magenta). Butterflies and fish respawn around the player; `Update` takes the `Atmosphere`: butterflies go from `DayButterflies` (30) by day to `ButterflyCount` (90) at night (extras are simply not respawned). Fish spawn only in open water (at least `FishSpawnDepth` deep, with water `FishMinDepth` deep for `FishSpawnClearance` metres all around); each keeps to a minimum depth (`FishMinDepth`, or `BraveFishMinDepth` for one in `BraveFishEvery`): when the water 5 m ahead gets shallower it turns toward the nearest heading that stays deep (`TryDeepHeading`), and despawns if it finds none or ends up in water half that depth. Deep fish (`CreatureKind.DeepFish`, bigger deep-bodied mesh with fins and glowing flank spots, one of four glows per school via the phase band of 20) swim in `DeepSchools` (3) schools of 3–6 within `DeepRange`, born only where the water is `DeepSpawnDepth` deep and stays `DeepMinDepth` deep for `DeepClearance` metres all around (`AcceptSchool`), at least `SchoolSpacing` apart (they also steer away from each other). A school is a point that roams at its own level (the whole school kept clear of bottom and surface), meandering and turning at a limited `TurnRate` away from other schools and toward deep water (probing 12 m ahead and both flanks, `TryDeepHeading` with a longer reach). Its fish are not a rigid formation (that made them move in lockstep): each is its own swimmer with a heading that turns at most 1 rad/s, a pace between 40% and 180% of the school's, and its own lag (`_deepResponse`), easing toward a slowly drifting place (`SchoolTarget`, slots at least `MinGap` fish lengths apart from `SchoolSlot`), steering away from and, if needed, nudged apart from its neighbours. Seven bird flocks of different sizes (2 to 12) fill the day sky; as the sun sinks below ~21° (sun Y 0.36 → 0.2, i.e. from the late afternoon into the evening twilight) they leave, until only `NightFlocks` (1: the first flock, a pair) stays through the evening and night: each flock has an eased `Presence` that widens its orbit out to `FlockAwayDistance` and hides it, so flocks fly in and out instead of popping. Flocks are never neat (no files or lines): ragged, lopsided Vs with uneven arms, gaps and stragglers, clouds, two or three knots drifting apart and together, and swirling balls; each bird has its own random spot and quirks (`_birdSlots`, `_birdQuirks`), wanders around it at its own pace, and every flock slowly stretches and squeezes. Flocks of different spacing, height and orbit direction wheel around an anchor that follows the player, each bird drifting around its slot. Flock altitude follows `SmoothHeight`, eased, never the layered tiles (their steps made flocks jump).

**Snow (`Weather`, `SnowRenderer`).** Key 3 toggles snow (rain and snow stop each other); `Weather.Snow` eases like the rain, and `Weather.SnowCover` grows while it snows (full in ~75 s) and melts afterwards (~3 min, faster in rain); both go out with the sky uniforms (`uSnow`, `uSnowCover`). `snowOn(pos, up)` in `SkyRenderer.Glsl` says how much snow lies on a surface: a snow line that starts on the heights and creeps down to the shores as the cover grows, only on up-facing surfaces, in noise drifts; the terrain, grass, tree and object fragment shaders mix their albedo toward `SnowColor` with it (not emissive parts). Snow closes the clouds and turns the sky pale blue-grey; `PostProcess.Finish(night, cold)` drains colour toward a cold blue-grey. `SnowRenderer`: 9000 point-sprite flakes, no vertex data, drifting and swaying in a box round the camera, premultiplied blending. `MINE_SNOW=1` starts with the snow already lying.

**Rain (`Weather`, `RainRenderer`).** Key 2 toggles rain; `Weather.Rain` eases in (~8 s) and out (~12 s) and is published as `SkyRenderer.Rain` → `uRain` with the sky uniforms. It lowers the cloud coverage threshold (overcast, and more cloud shadow), dims the sky toward a glowing indigo, veils the sunlight (×0.55) and thickens the mist (×3.5), hides most motes, and on the water adds ring ripples (`rainRings`, one layer of cells, computed once per pixel for both the normal and the glow) that bend the normal and glow faintly. `RainRenderer` draws 20000 drops with no vertex data (like the motes): very thin camera-facing quads along a slanted fall in a box following the camera, additive, faint uncoloured silver (the user did not want coloured rain), never thinner than ~0.7 px (fainter instead, so they do not flicker); drops appear one by one as the rain thickens; not drawn under water. Keep the magic, cosmic tone in the sky and water (no dull greys), but the drops themselves stay colourless.

**Motes (`MoteRenderer`).** 1800 additive point sprites with no vertex data: each derives position, drift and colour from `gl_VertexID`, wrapped in a box that follows the camera; golden sparkles by day, lilac spores at dusk, blinking fireflies at night, fading out when flying high.

**Decorations.** `TreeModels.Decoration` (violet and cyan crystal clusters, lotus flowers, glow bells, palms in three builds (`Palm`, `TallPalm` 13 m and deeply curved, `ShortPalm` 4.6 m and stocky, picked by `TreeField.RandomPalm` with instance scales 0.7–1.35 so no two match), reed clumps, and flowers: daisies, tulips, glowing starflowers, lupins with glowing tips, all bare stems; and flowers born of light built by `LeafyFlowers` (colours from `PaletteOf`): pale glowing stems (`GlowTube`) with tinted leaves along them (phyllotaxis) whose midribs glow (`ribGlow`), each stem crowned by a flower and branching near the top into 2–3 curved side stems with smaller flowers or buds (a bract at each fork), a calyx, heads (`Head`) of curved cupped neon petals (`Petals`) glowing toward the tips, shining stamens, floating seeds of light, the odd closed bud; leaves, petals and sepals are all `Blade` surfaces (curving in one plane, folded, pointed or rounded): violet irises with sword-leaf fans, magenta poppies on leaf rosettes, cyan lilies with recurved petals. Each kind also casts a coloured light (`TreeModels.FlowerLight`): `TreeField.FlowerLights` returns the nearest 8 within 14 m, faded toward a cutoff that follows the distance of the first one left out so lights never pop, merged with the crystals' lights in `CollectLights`; flowers are scaled up (instance scale over 1) to stand above the grass) are extra variants after the tree styles, drawn by the same instanced `TreeRenderer` (so they get wind, shadows, emissive glow and levels of detail). `TreeModels.MaxDistance` hides small plants sooner; `TrunkRadius` 0 means no collision; `CastsShadow` keeps small flowers out of the shadow map. `TreeField.AddDecorations` samples 20 points per cell and decorates by ground type: lotus on the shallows (at the water level), palms and crystals on the shores, the odd crystal on steep rock, glow bells in noise patches on meadows. `TreeField.AddFlowers` samples 40 more points per cell: in meadows, everywhere in moderation (a little thicker in patches), one kind dominating each area with others mixed in; under the woods (same forest noise as the trees), starflowers and bells. Each biome has its meadow flowers (indigo: lupins, starflowers; pink: tulips, daisies; turquoise: starflowers, daisies; deserts: the odd starflower), the dominant one from bands of a species noise. The flowers born of light grow only in `TreeField.AddLightGardens` (45 samples per cell): gardens only under the woods, where a garden noise is positive, densest at their heart and where the forest noise is highest (thick woods); the biome picks the kind (irises indigo, poppies pink, lilies turquoise), none in deserts. Deserts also grow crystal clusters from the sand. `TreeField.AddPalmGroves` (30 samples per cell) gathers palms in groves where a grove noise is high, thickest up to 3 m above the water and thinning out by 12 m (a few inland). `TreeField.AddReeds` scatters reed clumps (round stems with bulrush heads; instance scale low, middling or towering) over some tiles of the reed beds (`GroundMaterials.Reeds`) from 1.2 m under to 1 m over the water. Crystal clusters within 80 m also become point lights (`TreeField.GlowingLights`, merged with the objects' lights by distance in `WorldObjects.CollectLights`). The bloom prefilter uses a Karis average so lone super-bright pixels (e.g. glints through pixel cracks) do not bloom into blobs.

**Objects and lights.** `WorldObjects` (src/World/WorldObjects.cs) holds the collectable objects, currently only small glowing crystals (`ObjectKind.Crystal`): generated ones (deterministic per 64 m cell, within `ActiveRadius`, only on gentle ground; positive ids, picked-up ids remembered in `_taken` so they never respawn) and placed ones (negative ids). `ObjectDefs` gives each kind its name, light colour/intensity/radius/height and pick capsule. `Pick` finds the object whose vertical capsule the view ray passes nearest along the ray; `TerrainField.Raycast` (march + bisection) finds where to place. Left click picks up the aimed object into the inventory, right click places a crystal on the aimed ground within `ReachDistance`. `CollectLights` returns the `MaxPointLights` (16) nearest lights with the crystals' slow pulse, uploaded as uniform arrays each frame; point lights are dimmed in daylight. `ObjectRenderer` builds one flat-shaded procedural mesh per kind (position, normal, colour, emissive) drawn per object with a model matrix; emissive parts glow and cut through haze, the aimed object is highlighted. Objects cast sun shadows via `ShadowMap.SetCasterModel`.

**Lighting and sky.** `DayCycle` (src/World/DayCycle.cs) holds the time of day (0 = midnight, 0.5 = noon; 20-minute cycles; the game starts at 8:00) and interpolates colour keyframes (night, dawn, twilight, day, noon, dusk: all violet/pink, noon clearer and bluer) into an `Atmosphere`. The sun circles low for long twilights, then climbs for a short bright noon: its elevation is `SunMid + SunSwing * w + SunPeak * w⁴` (w = sin(azimuth), the last term only when positive), peaking at ~54° and above 30° for about a sixth of the cycle; a high sun's light is up to 35% stronger; the moon (drawn as a giant crescent planet, `PlanetSize` ≈ 20° radius, lit mostly from behind with a glowing lilac-magenta limb and faint glowing cracks, two small moons beside it; `planetSurface`, `moonHalo`) rides opposite and high at night; auroras (`aurora`: curtains of rays over a few noise-chosen stretches of the horizon, cyan foot, blue, magenta tips) hang in front of the sky bodies at night; night clouds are lit magenta; the galaxy direction drifts slowly, always well above the horizon, with `GalaxyGlow` rising at night. The sky shader adds the galaxy (five log-spiral arms of uneven strength (`armIndex`, changing in the dark lanes), bent asymmetrically by a broad sky noise and made wavy and clumpy by the cloud noise, with spurs between them, dark dust lanes, cyan clouds, a gentle core and bulge the arms emerge from, spherical rim, star dust), nebula veils (cloud noise), denser stars and shooting stars (`shootingStar`/`streak`: one 9 s slot in two, gliding 40–90° along a great circle in 3–4.5 s, the tail (17–31°) measured along the circle, fading out over the second half; key 1 launches one across the view for debugging via `SkyRenderer.LaunchShootingStar`, visible by day too). Shooting stars burn up in the atmosphere, so they are added last, in front of the moon, galaxy and nebulae (clouds still hide them). The terrain has twinkling glitter grains (thickest on sand). `SkyRenderer` draws the sky as a full-screen triangle (gradient with a warm sun-side horizon, small square sun, round moon, twinkling stars, a cloud layer moved by `DayCycle.Elapsed`). Warm `Day` keyframes lead from the twilights into the `Noon` keyframe (0.47–0.53). `SkyAngle` (stars, nebulae, galaxy drift) comes from `Elapsed`, not `TimeOfDay`, so it never jumps at midnight. The galaxy is dramatic but soft (broad arms, noise via coarse mips, soft lanes, wide rim); keep the arm count a whole number (no seam) and measured by angle from its centre (rim at ~68°), so it never fits on screen; its streak noise is sampled through cos/sin of the swirl to avoid a seam. Its `Glsl` constant (sky uniforms, `skyColor()`, `toneMap()`, `hash13()`) is pasted into both the sky and the terrain fragment shader, so fog takes the exact sky colour in the view direction. The terrain adds a soft aerial haze that tints distance with the hue of the sky while keeping brightness (no whitening), and an edge fog to the sky colour over the last quarter of the view distance.

**Shadows (`ShadowMap`).** Each frame the caller's `drawCasters` draws the geometry around the player into a 2048² depth texture from the light direction, with an orthographic box of half-width `Radius` (150 m) centred on the player and snapped to texels. The light direction follows the sun every frame, so shadows move smoothly (it used to follow in steps of ~0.25°, which with a low sun made a tall tree's shadow tip jump by metres). To keep edges from crawling as the view turns, the light view turns about a pivot near the player snapped to `PivotCell` (32 m), not about the world origin: the texel grid then drifts over the nearby world by only hundredths of a texel per frame. Tree leaves' quick shiver is left out of the shadow pass (`treeWorld(..., shiver: 0)`), which made shadows flicker. The pass stores the faces turned toward the light (back faces culled as usual) with polygon offset; together with a normal offset and a tiny bias in the shader this avoids acne while keeping shadows attached. The terrain shader samples it as `sampler2DShadow` (texture unit 0, 3×3 PCF) for direct light only.

**Player.** The game starts at `Game.Spawn` (-517, 128: a meadow by a lake, on the terrain height; `MINE_POS` overrides it). `Player.Position` is the feet. It walks on `Ground.Height` (terrain tiles and island tops): walls up to `StepHeight` (one layer) are climbed by walking and steps down up to `GroundSnap` (two layers) are followed, the camera easing both ways via `_stepOffset`; for `GroundGrace` after leaving the ground the player still counts as grounded for climbing, so stepping between layers never stutters;, higher ones block horizontal motion (probed `Radius` ahead) unless the feet are already above them (jumping clears ~1.2 m); `GroundSnap` follows steps down. Below `WaterLevel - SwimDepth` the player swims: 3D movement like flying but slow with heavy drag (`SwimSpeed`, `SwimAccel`, `SwimDrag`), Space/Shift up/down, idle buoyancy toward `FloatDepth`, ledges up to `SwimClimb` can be climbed out onto. Under water, world shaders (`uUnderwater` in `finishColor`) fade into an indigo murk, the water surface is shaded as seen from below and the sky shader outputs the murk. Movement has inertia (exponential approach), double-tap W to sprint, Shift to sneak (slower, lower camera), F to fly, T to speed up time, 1 to launch a shooting star (debug), 2 to toggle the rain.

**Math conventions.** `System.Numerics` matrices (row-vector convention) are uploaded untransposed, and shaders compute `uViewProj * vec4(pos, 1)`. So on the C# side the combined matrix is `view * projection`. Its projections map depth to [0, 1] in NDC, which GL then maps to window depth [0.5, 1]; `ShadowMap.DepthBias` accounts for that.

Namespace gotcha: `Silk.NET.OpenGL` also defines `Shader`. Files outside `Mine.Rendering` that import it need `using Shader = Mine.Rendering.Shader;`.
