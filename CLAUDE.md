# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

An exploration game with smooth, dreamlike landscapes (inspired by Journey, Stray, Genshin Impact), in C# / .NET 10 using Silk.NET 2.23 (windowing, input, OpenGL). It started as a Minecraft clone: the block-based version lives on `main` (and `vegetazione-blocchi` adds swaying grass to it); this branch (`terreno-realistico`) replaces the blocks with a continuous terrain. Targets Windows, Linux and macOS, so portability matters: keep the GL context at **3.3 core + forward-compatible** (macOS caps at 4.1) and avoid platform-specific APIs. The user communicates in Italian; in-game UI strings (window title HUD) and README are in Italian.

Roadmap on this branch: 1) smooth terrain (done), 2) objects the player can pick up and place with point lights (done; for now only small glowing crystals, lanterns and torches were removed pending a redesign), 3) instanced grass and procedural trees swaying in the wind (done), 4) post-processing (bloom, light shafts, grading), volumetric clouds, surreal elements (done). Then the **cosmic direction**, modelled on AI "cosmic purple beach" art the user shared: a violet/indigo/magenta world with cyan accents, a giant spiral galaxy, bioluminescence everywhere, dark silhouettes. The day/night cycle stays, but its brightest moment is a twilight. Phases: A) sky, palette and cycle (done), B) water with sky reflections and a bioluminescent shore (done), C) giant crystal clusters and glowing flowers (done), D) crystal stepping-stone paths (tried, removed: the stones could not be climbed), E) creatures (butterflies, birds, fish) and palms (done).

## Commands

```
dotnet build                 # debug build
dotnet run -c Release        # play
dotnet publish -c Release -r <win-x64|linux-x64|osx-arm64> --self-contained -p:PublishSingleFile=true
```

`GpuPreference` (src/GpuPreference.cs) sets the Windows per-app "High performance" GPU preference for the running exe at startup and, the first time, restarts the game once so the discrete GPU is used.

There are no tests and no linter. The SDK lives at `C:\Program Files\dotnet\dotnet.exe`; if `dotnet` is not on PATH in the current shell, call it by full path. To verify rendering changes, launch `bin\Debug\net10.0\Mine.exe`, screenshot its window and kill the process (the game captures the mouse in raw mode while focused).

## Architecture

`Game` (src/Game.cs) owns the window, input callbacks, the inventory and the world shaders, and drives the loop: `Player.Update` → `DayCycle.Update` → `TreeField.Update` (+ trunk collision) → `TerrainRenderer.Update` → `TreeRenderer.Update` → `GrassRenderer.Update` → `WorldObjects.Update` (+ aim), then collect point lights → render shadow map (terrain + trees + islands + objects) → `PostProcess.BeginScene` (HDR buffer) → terrain → grass (culling off) → trees → objects → islands → sky (last, see below) → motes → `PostProcess.Finish` (bloom, grading to the screen) → crosshair. All scene shaders output linear HDR; tone mapping lives only in the composite pass. The window title is the HUD. Units are metres; Y is up.

**Terrain shape (`TerrainField`).** The land is layered: square tiles of `TileSize` (2 m), each flat at a multiple of `LayerHeight` (0.5 m), with vertical walls between. `SmoothHeight(x, z)` is the continuous surface they are cut from (2D `PerlinNoise`: continental swells, domain-warped hills, round-crested dune ridges, detail, rare rock spires; slopes are kept gentle so ~99.5% of neighbouring land tiles differ by at most one layer (walkable), larger steps being rare; below `WaterLevel` the land drops `DepthScale` times faster, so shores stay gentle and the water gets deep). `Height(x, z)` = `TileHeight` = the smooth height at the tile centre snapped with `Layer`. `Normal` is the smooth surface's normal (used for "how steep", e.g. where trees and crystals may grow). `InsideTile`/`TileCenter` keep things placed on a tile's flat top. Pure and thread-safe; no stored terrain data.

**Terrain rendering (`TerrainRenderer`).** Chunks of 64 m out to `ViewDistance` (1300 m). Each chunk is a grid of flat blocks (terrain tiles near the camera, merged 2×2, 4×4… farther away per `LodSteps`/`LodRanges`, each merged block at the layered height of its centre) plus vertical walls where neighbouring blocks differ; walls on the chunk border reach deeper (skirts) to hide cracks against other levels of detail. Non-indexed triangles, vertex layout position, normal, slope (smooth normal.y: picks the material, 0 on walls → rock), ao (walls darker at the foot). Meshes are built on background worker threads fed by a `BlockingCollection`, nearest first, and uploaded on the main thread at most `UploadsPerFrame` per frame; a chunk keeps drawing its previous mesh until the new one arrives, and stale results are dropped. `Draw` skips tiles well behind the camera; `DrawNear` draws only the tiles around a point for the shadow map.

**World shaders (`TerrainShaders`).** Terrain and object shaders share the private `Lighting` GLSL (pasted after `SkyRenderer.Glsl`): `litColor` = albedo × (generous ambient mixing the keyframe ambient with the sky colour around the normal + Lambert sunlight × shadow map + point lights), and `finishColor` = aerial haze + light halos + edge fog + tone map. Terrain materials are procedural, from slope and height: grass (drifting between green, golden and a teal accent), warm sandstone with faint wavy strata on steep slopes, pale sand in the lowlands, plus grain that fades with distance.

**Shared GLSL.** `SkyRenderer.Hash` (`hash13`, any stage) and `SkyRenderer.Glsl` (sky; fragment only, it uses `fwidth`). In `TerrainShaders`: `Wind` (`windOffset`), `TreeTransform` (`treeWorld`, used by both the tree shader and the shadow pass), `Materials` (noise, `grassColor`, `rockSand`), `Lighting`. Defining `CHEAP` before `Lighting` (grass) uses one shadow tap, no haze noise and no halos. `GroundMaterials` (src/World) is a C# mirror of `grassColor`/`rockSand` so grass is coloured and culled on the CPU: keep the two in sync.

**Grass (`GrassRenderer`).** 32 m tiles within `Radius` (70 m), built on the thread pool: blades scattered at `BladesPerSquareMetre` (more in tall meadows) with heights interpolated from a 1 m grid, kept only where `GroundMaterials.GrassWeight` says grass, and uploaded as one instance buffer per tile (root, bend, facing, height, thinning key, colour variation, ground colour). Grass colour comes in patches of one hue (teal, violet, magenta, lilac gold, sky blue: `grassColor`/`GrassColor`, kept in sync). No blades grow below 1 m over the water: the shores hold reed clumps instead (see Decorations). Blade height is `MinHeight` plus a random share of a maximum that grows in the tall grass meadows (`GroundMaterials.TallGrass`: thigh-high, and over head height in their hearts; taller blades are broader). Each blade is a shared 7-vertex triangle strip shaped in the vertex shader, which thins blades out with distance (survivors get wider) and sways the tips with the wind. Blades are lit with a wrapped diffuse, a normal turned toward the camera horizontally only, and backlight when looking toward the sun.

**Trees.** `TreeField` (src/World) places trees per 32 m cell on the thread pool, within `Radius` (950 m): dense where a forest noise is high, the odd lone tree elsewhere, only on gentle ground above the sand and never in tall grass meadows; a biome noise picks a family of models per region, and within it each grove (Voronoi regions around points jittered on an 80 m grid, `GroveSpecies`) is dominated by one species, with `OtherSpeciesChance` of another. `ResolveCollision` pushes the player out of trunks. `TreeModels` builds 13 procedural styles (incl. a 15 m giant, a weeping willow, a tiered pine, a sapling and a shrub) (tapering curved trunk, branches, crowns of noise-displaced ellipsoid blobs; two with glowing orbs) at 4 levels of detail from the same random structure, the last one a single-ellipsoid silhouette. Vertex layout: position, normal, colour, emissive, sway (0 at the trunk foot, 1 on leaves). `TreeRenderer` draws one instanced batch per variant and level (instances: position, yaw, scale), re-sorting into levels when the tree set changes or the camera moves 8 m; levels 0–1 (within 170 m) also cast shadows through the shadow map's instanced path (`SetInstanced`).

**Post-processing (`PostProcess`).** The scene renders into an RGBA16F colour + 24-bit depth texture framebuffer (at 70% resolution in low quality). Bloom: 13-tap downsample chain over 6 half-size levels (the first with a soft threshold, `BloomThreshold`), tent-filter upsample added back with additive blending. (Screen-space light shafts were removed: their radial blur stamped rows of blobs.) The bloom prefilter and the composite turn NaN/inf pixels black and cap the rest, since some GPUs produce NaNs where others do not (keep GLSL `pow` bases non-negative for the same reason). Composite: scene + bloom + shafts, exposure, the soft-shoulder tone map, saturation, split toning, vignette, dither.

**Sky and clouds.** The sky is drawn after the opaque geometry, at the far plane with `DepthFunc(Lequal)` and no depth writes, so its cost is paid only on visible sky pixels. Clouds are ray-marched through a slab (`CloudBottom`–`CloudTop`) in `SkyRenderer`: `cloudDensity` samples `CloudNoise` (a tileable 64³ R8 texture generated at startup, bound to unit `SkyRenderer.CloudNoiseUnit`), blurred via `textureLod` as steps grow; each sample marches a few steps toward the light for self-shadowing, with a two-lobe Henyey-Greenstein phase (silver lining) and interleaved-gradient-noise jitter. `cloudDensity` is part of `SkyRenderer.Glsl`, so the world shaders use it for moving cloud shadows (`cloudShadow` in `Lighting`). Quality: `SkyRenderer.LowQuality`/`PostProcess.LowQuality` (fewer cloud and shaft samples, lower render scale), chosen at startup from the GL renderer string (Intel/llvmpipe → low) and toggled with Q.

**Water.** `TerrainField.WaterLevel` (15 m) is the sea and lake level; sand covers the shores just above it (keep `rockSand` in the shader and `GroundMaterials` in sync), trees stay 5 m above it, grass 1 m. `WaterRenderer` draws one quad at that level following the camera (culling off); the terrain hides it wherever it rises above. Before the water, `PostProcess.SnapshotForWater` blits the scene colour and depth into copies (units 3 and 4) so `TerrainShaders.WaterFragment` can refract the bottom (bent by ripples, absorbed toward deep indigo with the view-space thickness, from linearized depths) and reflect `skyColor(r, true)` with Fresnel, plus a glint path toward the light and bioluminescence (ridged-noise veins pulsing in the shallows, a glowing line at the shore, sparkles). `Ground` keeps the player's feet at most `WadeDepth` below the surface. Order: opaque → sky → water → motes.

**Floating islands.** `IslandField` (src/World) places at most one island per 420 m cell within 1700 m, 70–190 m above the land, with trees on top (added to `TreeField` via `SetFixedTrees` when `IslandField.Version` changes). `EdgeRadius`/`TopHeight` define the top and are shared by `IslandRenderer` (meshes built on the thread pool: a tube of rings from the domed top down the rocky underside, smooth normals, hanging emissive crystals via `MeshBuilder`) and by `GroundBelow`, which `Ground` (src/World/Ground.cs) combines with the terrain so the player can land on islands. Islands are drawn with the object shader (identity model matrix) and cast shadows.

**Creatures (`Creatures`, `CreatureRenderer`).** Butterflies and fish respawn around the player; five bird flocks of different sizes (2 to 16), formations (V, echelon, single file, loose cloud), spacing, height and orbit direction wheel around an anchor that follows the player, each bird drifting around its slot.

**Motes (`MoteRenderer`).** 1800 additive point sprites with no vertex data: each derives position, drift and colour from `gl_VertexID`, wrapped in a box that follows the camera; golden sparkles by day, lilac spores at dusk, blinking fireflies at night, fading out when flying high.

**Decorations.** `TreeModels.Decoration` (violet and cyan crystal clusters, lotus flowers, glow bells, palms, reed clumps) are extra variants after the tree styles, drawn by the same instanced `TreeRenderer` (so they get wind, shadows, emissive glow and levels of detail). `TreeModels.MaxDistance` hides small plants sooner; `TrunkRadius` 0 means no collision. `TreeField.AddDecorations` samples 20 points per cell and decorates by ground type: lotus on the shallows (at the water level), palms and crystals on the shores, the odd crystal on steep rock, glow bells in noise patches on meadows. `TreeField.AddReeds` scatters reed clumps (round stems with bulrush heads; instance scale low, middling or towering) over some tiles of the reed beds (`GroundMaterials.Reeds`) from 1.2 m under to 1 m over the water. Crystal clusters within 80 m also become point lights (`TreeField.GlowingLights`, merged with the objects' lights by distance in `WorldObjects.CollectLights`). The bloom prefilter uses a Karis average so lone super-bright pixels (e.g. glints through pixel cracks) do not bloom into blobs.

**Objects and lights.** `WorldObjects` (src/World/WorldObjects.cs) holds the collectable objects, currently only small glowing crystals (`ObjectKind.Crystal`): generated ones (deterministic per 64 m cell, within `ActiveRadius`, only on gentle ground; positive ids, picked-up ids remembered in `_taken` so they never respawn) and placed ones (negative ids). `ObjectDefs` gives each kind its name, light colour/intensity/radius/height and pick capsule. `Pick` finds the object whose vertical capsule the view ray passes nearest along the ray; `TerrainField.Raycast` (march + bisection) finds where to place. Left click picks up the aimed object into the inventory, right click places a crystal on the aimed ground within `ReachDistance`. `CollectLights` returns the `MaxPointLights` (16) nearest lights with the crystals' slow pulse, uploaded as uniform arrays each frame; point lights are dimmed in daylight. `ObjectRenderer` builds one flat-shaded procedural mesh per kind (position, normal, colour, emissive) drawn per object with a model matrix; emissive parts glow and cut through haze, the aimed object is highlighted. Objects cast sun shadows via `ShadowMap.SetCasterModel`.

**Lighting and sky.** `DayCycle` (src/World/DayCycle.cs) holds the time of day (0 = midnight, 0.5 = the brightest twilight; 20-minute cycles) and interpolates colour keyframes (night, dawn, twilight, dusk: all violet/pink) into an `Atmosphere`. The sun circles low: its elevation is `SunMid + SunSwing * sin(azimuth)`, at most ~8° above the horizon; the moon rides opposite and high at night; the galaxy direction drifts slowly, always well above the horizon, with `GalaxyGlow` rising at night. The sky shader adds the galaxy (log-spiral arms broken up by the cloud noise, bright core, spherical rim, star dust), nebula veils (cloud noise), denser stars and a shooting star every few seconds. The terrain has twinkling glitter grains (thickest on sand). `SkyRenderer` draws the sky as a full-screen triangle (gradient with a warm sun-side horizon, round sun and moon, twinkling stars, a cloud layer moved by `DayCycle.Elapsed`). The sun's elevation peaks at ~25° (`SunMid`/`SunSwing`), with a warm `Day` keyframe between the twilights. `SkyAngle` (stars, nebulae, galaxy drift) comes from `Elapsed`, not `TimeOfDay`, so it never jumps at midnight. The galaxy is measured by angle from its centre (rim at ~68°), so it never fits on screen; its streak noise is sampled through cos/sin of the swirl to avoid a seam. Its `Glsl` constant (sky uniforms, `skyColor()`, `toneMap()`, `hash13()`) is pasted into both the sky and the terrain fragment shader, so fog takes the exact sky colour in the view direction. The terrain adds a soft aerial haze that tints distance with the hue of the sky while keeping brightness (no whitening), and an edge fog to the sky colour over the last quarter of the view distance.

**Shadows (`ShadowMap`).** Each frame the caller's `drawCasters` draws the geometry around the player into a 2048² depth texture from the light direction, with an orthographic box of half-width `Radius` (150 m) centred on the player and snapped to texels. The pass stores the faces turned toward the light (back faces culled as usual) with polygon offset; together with a normal offset and a tiny bias in the shader this avoids acne while keeping shadows attached. The terrain shader samples it as `sampler2DShadow` (texture unit 0, 3×3 PCF) for direct light only.

**Player.** `Player.Position` is the feet. It walks on `Ground.Height` (terrain tiles and island tops): walls up to `StepHeight` (one layer) are climbed by walking and steps down up to `GroundSnap` (two layers) are followed, the camera easing both ways via `_stepOffset`; for `GroundGrace` after leaving the ground the player still counts as grounded for climbing, so stepping between layers never stutters;, higher ones block horizontal motion (probed `Radius` ahead) unless the feet are already above them (jumping clears ~1.2 m); `GroundSnap` follows steps down. Below `WaterLevel - SwimDepth` the player swims: 3D movement like flying but slow with heavy drag (`SwimSpeed`, `SwimAccel`, `SwimDrag`), Space/Shift up/down, idle buoyancy toward `FloatDepth`, ledges up to `SwimClimb` can be climbed out onto. Under water, world shaders (`uUnderwater` in `finishColor`) fade into an indigo murk, the water surface is shaded as seen from below and the sky shader outputs the murk. Movement has inertia (exponential approach), double-tap W to sprint, Shift to sneak (slower, lower camera), F to fly, T to speed up time.

**Math conventions.** `System.Numerics` matrices (row-vector convention) are uploaded untransposed, and shaders compute `uViewProj * vec4(pos, 1)`. So on the C# side the combined matrix is `view * projection`. Its projections map depth to [0, 1] in NDC, which GL then maps to window depth [0.5, 1]; `ShadowMap.DepthBias` accounts for that.

Namespace gotcha: `Silk.NET.OpenGL` also defines `Shader`. Files outside `Mine.Rendering` that import it need `using Shader = Mine.Rendering.Shader;`.
